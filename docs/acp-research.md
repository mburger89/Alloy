# ACP (Agent Client Protocol) research for a Swift editor-side client
Researched 2026-11-19 from the official ACP docs and schema (v1) and the adapters' repositories; URLs per section.
Index: https://agentclientprotocol.com/llms.txt  (pages: https://agentclientprotocol.com/protocol/v1/<page>.md)
Stable = v1 (protocolVersion 1). v2 is a DRAFT (announced 2026-07-20); build v1 first.

## 1. Transport, framing, handshake, auth
Source: /protocol/v1/transports, /initialization, /authentication, /overview
- JSON-RPC 2.0, UTF-8. stdio transport: client spawns the agent as a subprocess; messages are newline-delimited (`\n`), MUST NOT contain embedded newlines. NOT Content-Length (unlike LSP). Agent stderr = free-form logs. Agent must write only valid ACP to stdout. Closing stdin + terminating the process ends the session. Streamable HTTP/WebSocket transport is only an RFD (/rfds/streamable-http-websocket-transport).
- Both sides send requests; IDs chosen independently per direction. Notifications have no response. Paths absolute, lines 1-based. Keys camelCase, discriminator string values snake_case. Extensions: `_meta` objects, custom methods prefixed `_`.
- Current protocolVersion: integer 1 (major only). Client sends the latest it supports; agent echoes if supported, else responds with its latest; client closes if unsupported.
- initialize request: `{protocolVersion:1, clientCapabilities:{auth:{terminal:bool}, fs:{readTextFile,writeTextFile}, terminal:bool, elicitation:{form?,url?}, session:{configOptions:{boolean:{}}, compaction:{}, notices:{}}}, clientInfo:{name,title,version}}`. Omitted capability = unsupported.
- initialize response: `{protocolVersion, agentCapabilities:{loadSession:bool, promptCapabilities:{image,audio,embeddedContext}, mcpCapabilities:{http,sse}, auth:{logout:{}}, sessionCapabilities:{list,resume,close,delete,fork?,additionalDirectories,systemPrompt:{mode:{override:{}}}}}, agentInfo:{name,title,version}, authMethods:[...]}`. Baseline prompt content every agent must accept: text + resource_link. Image/audio/resource(embedded) are gated by promptCapabilities. MCP: stdio mandatory; http/sse gated by mcpCapabilities.
- Auth: `authMethods[]` entries `{id,name,description,type?}`. Default type "agent": client calls `authenticate {methodId}` -> `{}`. Type "terminal" (needs clientCapabilities.auth.terminal=true): client re-launches the same agent command with the method's `args` (+`env`) in an interactive terminal, exit 0 = success, then reconnects and re-sends initialize; client must NOT call authenticate for it. `logout` method if agentCapabilities.auth.logout. Unauthenticated calls fail with error -32000 `auth_required`. Env-var style auth (API keys) is done by the client setting env when launching the agent, not via ACP. OpenCode additionally reads `clientCapabilities._meta["terminal-auth"]=true` (https://opencode.ai/docs/acp/) for an older-style terminal login descriptor.
- Error codes: -32700/-32600/-32601/-32602/-32603, -32800 request cancelled, -32000 auth required, -32002 resource not found (unknown session/file/terminal). https://agentclientprotocol.com/protocol/v1/error.md
- `$/cancel_request` notification (stabilized) cancels any in-flight request; receiver must still respond (e.g. cancelled stop reason or -32800). /protocol/v1/cancellation

## 2. Session lifecycle
Source: /protocol/v1/session-setup, /prompt-turn, /session-modes, /session-config-options, /slash-commands, /session-list
- `session/new {cwd (absolute), mcpServers[], additionalDirectories?, systemPrompt?}` -> `{sessionId, modes?, configOptions?}`. cwd governs the session regardless of where agent was spawned.
- mcpServers shapes: stdio `{name, command (abs path), args[], env:[{name,value}]}` (no `type` field); http `{type:"http", name, url, headers:[{name,value}]}`; sse `{type:"sse", name, url, headers:[...]}` (deprecated). (There is also an "acp" MCP-over-ACP type, RFD only; claude-agent-acp supports `"type":"acp"`.)
- `session/load {sessionId,cwd,mcpServers}` (needs loadSession): agent replays whole history as session/update (user_message_chunk, agent_message_chunk, tool_call...), then responds `{}` (may include modes/config). `session/resume` (sessionCapabilities.resume) = same but NO replay. `session/close` (sessionCapabilities.close) cancels + frees; idempotent (-32002 = treat as success). `session/list` (cwd filter, cursor, ~100/page) and `session/delete` are stable. `session/fork` appears supported by OpenCode (stability unconfirmed; RFD /rfds/session-fork).
- `session/prompt {sessionId, prompt: ContentBlock[]}` -> `{stopReason}` when the turn ends. Stop reasons: end_turn, max_tokens, max_turn_requests, refusal, cancelled. One prompt at a time per session (OpenCode errors on a second concurrent prompt).
- ContentBlock (superset of MCP 2025-06-18): `{type:"text",text}`, `{type:"image",data(b64),mimeType,uri?}`, `{type:"audio",data,mimeType}`, `{type:"resource",resource:{uri,text|blob,mimeType?}}` (embedded; preferred for @-mentions), `{type:"resource_link",uri,name,mimeType?,title?,description?,size?}`; all with optional `annotations`.
- `session/cancel` (notification `{sessionId}`): client SHOULD immediately mark pending tool calls cancelled locally and MUST answer all pending session/request_permission with outcome `cancelled`; agent finishes pending updates then returns prompt response with stopReason `cancelled` (must not surface abort exceptions as errors). Client should keep accepting late tool_call_updates.
- Modes (legacy, to be removed): session/new response `modes:{currentModeId, availableModes:[{id,name,description?}]}`; client `session/set_mode {sessionId,modeId}`; agent pushes `current_mode_update {currentModeId}`.
- Config options (preferred, replaces modes/model methods): `configOptions:[{id,name,description?,category?("mode"|"model"|"model_config"|"thought_level"|_custom),type:"select"|"boolean",currentValue,options:[{value,name,description?}] or groups[{group,name,options}]}]`; set with `session/set_config_option {sessionId,configId,value}` (boolean: also `type:"boolean"`) -> full updated configOptions list; agent can push `config_option_update`. Model selection = the option with category "model" (stabilized: /announcements/model-config-category-stabilized). The old `session/set_model` is UNSTABLE (Gemini CLI still exposes `unstable_setSessionModel`, https://geminicli.com/docs/cli/acp-mode/). Boolean options require client capability session.configOptions.boolean.
- Slash commands: `available_commands_update {availableCommands:[{name,description,input?:{hint}}]}`; invoked simply by sending a normal text prompt "/name args".
- Other stable pieces: `session_info_update` (title/updatedAt), additionalDirectories, systemPrompt (append/override), elicitation (`elicitation/create` form/url, client-side request), session notices, compaction updates.

## 3. session/update variants (notification `session/update {sessionId, update:{sessionUpdate:<tag>,...}}`)
Source: /protocol/v1/prompt-turn (table), /tool-calls, /agent-plan, /content
- user_message_chunk / agent_message_chunk / agent_thought_chunk: `{content: ContentBlock, messageId?}` (same messageId = same message; changed id = new message).
- tool_call: `{toolCallId, title, name?, kind?, status?(default pending), content?[], locations?[], rawInput?, rawOutput?}`. kind: read, edit, delete, move, search, execute, think, fetch, switch_mode, other. status: pending, in_progress, completed, failed.
- tool_call_update: `{toolCallId, ...any subset of the above}` (only changed fields; null/omitted rawInput/rawOutput = unchanged). 
- ToolCallContent variants: `{type:"content",content:ContentBlock}`, `{type:"diff",path(abs),oldText?(null=new file),newText}`, `{type:"terminal",terminalId}` (client shows live output, keeps showing after release). locations: `[{path,line?}]` (use for "follow the agent"; don't auto-open outside root set).
- plan: `{entries:[{content,priority:high|medium|low,status:pending|in_progress|completed}]}`; always full list, client replaces whole plan.
- available_commands_update, current_mode_update, config_option_update, session_info_update (see above).
- usage_update: `{used, size, cost?:{amount,currency}}` (stabilized; see 5).
- notice `{severity:info|warning|error,title,description?}` (only if client advertised session.notices; live, not replayed). compaction_update `{compactionId,status:in_progress|completed|failed|cancelled,summary?,error?}` and compaction_summary_chunk `{compactionId,content}` (only if session.compaction advertised).
- Clients must tolerate unknown variants/enum values (open enums, `_` prefix = extension). Unstable ones seen in the wild: prompt_suggestions_update (claude-agent-acp), cursor_update (v2).

## 4. Agent -> client requests (client must implement)
Source: /protocol/v1/tool-calls, /file-system, /terminals
- `session/request_permission {sessionId, toolCall:{toolCallId, ...partial ToolCallUpdate (title/kind/content/locations/rawInput...)}, options:[{optionId,name,kind}]}` -> `{outcome:{outcome:"selected",optionId}}` or `{outcome:{outcome:"cancelled"}}`. kinds: allow_once, allow_always, reject_once, reject_always. The AGENT owns remembering allow_always/reject_always (client only passes the selection). Option `name` describes scope. Client may auto-answer per user settings; must not auto-approve based only on title/name. Known issue: toolCall.rawInput can be lost (issue #1979 in agent-client-protocol).
- `fs/read_text_file {sessionId,path(abs),line?,limit?}` -> `{content}`; serves unsaved editor buffers (the main reason to implement). Missing file -> -32002. Only called if clientCapabilities.fs.readTextFile.
- `fs/write_text_file {sessionId,path,content}` -> `{}`; client MUST create file if missing. Client should path-check against session root set and ask before writing hooks/settings/MCP config.
- `terminal/create {sessionId,command,args?,env?[{name,value}],cwd?,outputByteLimit?}` -> `{terminalId}` (returns immediately, process runs in background; truncation from the front at char boundary). `terminal/output {sessionId,terminalId}` -> `{output,truncated,exitStatus?:{exitCode?,signal?}}`. `terminal/wait_for_exit` -> `{exitCode?,signal?}`. `terminal/kill` (terminal stays valid for output/wait). `terminal/release` kills if running and invalidates the id (UI should keep showing embedded output). Agent MUST release. Gate: clientCapabilities.terminal=true. Client should sanitize control sequences in displayed output.
- Also `elicitation/create` (if advertised); notification `elicitation/complete`.

## 5. Usage / cost / tokens
Source: https://agentclientprotocol.com/rfds/session-usage , /announcements/session-usage-stabilized, https://agentclientprotocol.com/rfds/end-turn-token-usage
- STABLE: session/update `usage_update {used, size, cost?:{amount,currency}}` = context-window tokens used / window size, cumulative cost (ISO 4217 or e.g. "credits"). Agent-optional.
- DRAFT RFD (not stable): `usage:{totalTokens,inputTokens,outputTokens,thoughtTokens,cachedReadTokens,cachedWriteTokens}` on the PromptResponse (v1) / idle state_update (v2). Real adapters already send it and disagree on semantics: claude-agent-acp #390 (per-turn vs RFD cumulative), codex-acp #447 (last request only). Treat as best-effort, display-only.
- No per-request cost for local models; `cost` will be absent.

## 6. Agents today (registry: https://agentclientprotocol.com/get-started/registry ; list: /get-started/agents)
Registry is curated, only agents with auth support; 50+ agents incl. Claude Agent, Codex, Gemini CLI, Copilot, Cursor, Goose, OpenCode, Cline, Junie, Kiro, Mistral Vibe, Qwen Code, Kimi, Auggie, Amp (wrapper), pi (adapter), Devin, Droid. Registry repo: https://github.com/agentclientprotocol/registry (machine-readable manifest; Swift pkg ACPRegistry reads it).
- Codex: adapter https://github.com/agentclientprotocol/codex-acp, npm `@agentclientprotocol/codex-acp`; launch `npx -y @agentclientprotocol/codex-acp` (bundles @openai/codex; `CODEX_PATH` overrides binary). It starts the Codex App Server and translates. Auth methods: ChatGPT login (browser; NO_BROWSER=1 hides), API key via CODEX_API_KEY / OPENAI_API_KEY, custom OpenAI-compatible gateway (client opt-in capability). Modes: read-only, workspace-write, agent, agent-full-access, permission profiles. FS: the adapter source has no non-test use of fs/read|write_text_file, so Codex edits files directly on disk in its own sandbox and reports changes as tool_call diff content (INFERRED from repo code search, not stated in docs; verify by running with fs caps on). Local model: env `MODEL_PROVIDER` and `CODEX_CONFIG` (JSON merged into Codex config) are the adapter hooks; underlying Codex supports `--oss` / `oss_provider="ollama"|"lmstudio"` and `[model_providers.x] base_url=http://localhost:11434/v1` (Ollama) / `http://localhost:1234/v1` (LM Studio) in ~/.codex/config.toml (third-party blogs; UNCONFIRMED against official docs and against codex-acp). Small local models without tool-calling "connect but never edit".
- Claude Code: https://github.com/agentclientprotocol/claude-agent-acp (formerly zed-industries/claude-code-acp, npm `@agentclientprotocol/claude-agent-acp`); `npx @agentclientprotocol/claude-agent-acp`; standalone binaries per OS in GitHub releases (bundled claude CLI, no Node needed; CLAUDE_CODE_EXECUTABLE overrides). Auth: uses Claude Code's own login, or ANTHROPIC_API_KEY. Issue #517 (open, 21 comments): claude.ai subscription login is not supported via the integration; users must `/login` in the CLI first and the adapter reuses it (Anthropic policy-dependent; check current status). FS: adapter has a client wrapper with readTextFile/writeTextFile and issue #94 says it re-maps Read/Write tools to ACP fs calls when the client offers them (so .claude/settings.json deny rules on reads were bypassed). Local model: Anthropic-API only; Bedrock/gateway via CLAUDE_CODE_USE_BEDROCK + CLAUDE_MODEL_CONFIG, and gateway routing via `providers/set` (draft RFD). Pointing at Ollama requires an Anthropic-compatible proxy (ANTHROPIC_BASE_URL) - UNCONFIRMED for this adapter.
- Gemini CLI: `gemini --acp` (older: `--experimental-acp`; check version) https://geminicli.com/docs/cli/acp-mode/ . Methods: initialize, authenticate, newSession, loadSession, prompt, cancel, setSessionMode, unstable_setSessionModel; docs state file access is proxied through the client's fs methods. Auth via Google login / GEMINI_API_KEY / Vertex. NOTE docs banner: Gemini CLI replaced by "Antigravity CLI" for free/Google One users on 2026-06-18 (Antigravity also listed in registry). No local-model path found (UNCONFIRMED).
- OpenCode: `opencode acp` (https://opencode.ai/docs/acp/). Stable v1 over newline-delimited stdio; caps loadSession, http MCP (no sse), image+embeddedContext, session list/resume/close/delete/fork/additionalDirectories. Auth: reuses `opencode auth login` credentials; method `opencode-login` (terminal type if client advertises auth.terminal -> client runs `opencode acp --login`). One prompt per session. cwd must equal the session's dir on load/resume. `--print-logs` for stderr debug. Provider-agnostic: configure an openai-compatible provider (Ollama/LM Studio baseURL) in opencode.json in the project cwd (per docs it uses cwd's config) - best candidate for local models. Whether it routes writes through fs/* is UNCONFIRMED (docs don't say).
- Goose: `goose acp` (https://goose-docs.ai/docs/gdk/acp/ , reference lists goose v1.60.1; block.github.io/goose now redirects to goose-docs.ai). Provider/model via GOOSE_PROVIDER / GOOSE_MODEL env (set in the client's agent env), Ollama via OLLAMA_HOST (default localhost:11434). Has many `_goose/unstable/*` custom methods. FS routing UNCONFIRMED. Goose can also itself consume ACP agents as providers (reverse direction).
- Cursor (`cursor-agent acp`, https://cursor.com/docs/cli/acp): forum report that it ignores clientCapabilities.fs and uses internal tools (https://forum.cursor.com/t/acp-honor-clientcapabilities-fs-for-file-delegation/153815). Copilot CLI `--acp`: issue github/copilot-cli#845 (closed) agent auto-approved tools without session/request_permission.
- Takeaway: do not assume fs/write_text_file is the write path. Many agents write to disk themselves and only report diffs/locations; plan a file-watcher/reload path plus diff rendering from tool_call content, and treat fs/* as the bonus path for unsaved buffers.
- Client-managed LLM routing is an open RFD: `providers/list|set|disable` (agentCapabilities.providers) to point any agent at a proxy/Ollama/vLLM base URL with apiType anthropic|openai|azure|vertex|bedrock: https://agentclientprotocol.com/rfds/custom-llm-endpoint (draft; claude-agent-acp and codex-acp already mention providers/set support).

## 8. Gotchas (from docs/issues; GitHub issue links where noted)
- Newline framing: agents must not print non-ACP to stdout; a single stray log line (e.g. a Node deprecation warning) breaks parsing. Be tolerant: skip/log unparsable lines, keep stderr separate. (claude-code-acp #69 "JSON parsing error"; OpenCode --print-logs note.)
- Agents may write files directly, bypassing fs/* (Cursor forum thread above; Codex adapter by code inspection). Also permissions: Copilot #845 auto-approved without asking; ACP discussion #928 proposes mandatory permission checks since write_text_file itself does no permission check - the client is responsible for path-scoping (root set) and prompting. https://github.com/orgs/agentclientprotocol/discussions/928
- Cancellation races: cancel must resolve all pending permission requests with `cancelled`; agent must still return stopReason cancelled; codex-acp #641 (open) cancel dropped when turn id mismatches; claude-agent-acp #825 prompt turn never terminated when model stream ends abnormally (session stuck "running") - add client-side watchdog/timeouts and a way to kill the process.
- Turn completion: session/update notifications can arrive after you think the turn is done and outside prompt turns (agent-client-protocol #554; replay on session/load; commands pushed right after session/new; usage updates). Don't gate UI state on the prompt response alone; v2 reworks this (prompt returns when accepted, idle state_update ends the turn).
- Session startup latency: claude-agent-acp #567 session/new took 11+ s; don't block UI, show spinner.
- Large output: terminal outputByteLimit truncates from the beginning; tool_call rawOutput/diff oldText+newText carry full file contents in one JSON line (can be MBs) - use a streaming line reader with a large/unbounded buffer, not fixed-size reads, and consider rendering lazily.
- Terminal lifecycle: agent must release; leaked terminals = leaked processes; kill all on session close/cancel/app quit. Terminal output can contain escape sequences (sanitize).
- Load vs resume: session/load replays history (do not double-append in UI; replay messages carry messageId); session/resume doesn't. Compaction/notice updates only if you advertise capabilities - only advertise what you render.
- Capability honesty: advertise only fs/terminal/elicitation you implement; agents `MUST NOT` call unadvertised methods (so omit fs write to force diffs-only path if you prefer).
- Auth: login flows differ per agent; support both `authenticate` and terminal-type auth (relaunch with args). Missing/expired creds surface as -32000 auth_required (codex-acp #495 once returned InternalError instead). Claude subscription login problems: #517.
- Usage numbers inconsistent across adapters (#390, #447).
- Permission request details: toolCall may carry only toolCallId (look up the earlier tool_call by id); rawInput may be missing (#1979).
- Version drift: spec iterates quickly (50+ RFDs, v2 draft with breaking changes: auth/login, session/prompt returns on accept, structured diffs, permission subject, required message IDs; migration guide https://agentclientprotocol.com/protocol/v2/migration). Negotiate protocolVersion 1 for now; agents like claude-agent-acp serve v1 unless client asks for >=2.
- Zed registry/auth: only agents with auth methods are in the registry; check `authMethods` empty = no auth needed.
