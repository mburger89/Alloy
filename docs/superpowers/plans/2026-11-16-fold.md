# Fold Sources Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the three data sources of code folding (indentation, tree-sitter, LSP `textDocument/foldingRange`) and the pure precedence merge, as tested `Sendable` line-range producers that a later fold coordinator consumes.

**Architecture:** One value type, `FoldRange` (0-based start and end line), lives in AlloyCore with `FoldSource` and a pure `FoldMerge.choose`. AlloyCore's `IndentFolds` keeps a per-document indent-per-line cache that edits splice and mark dirty, so a rebuild measures only dirty lines and then runs one integer stack pass. AlloyHighlight runs per-language fold queries on the whole-file tree it already keeps and caches the result per document version. AlloyLSP parses the answer and requests it through one small function on `LSPManager`. Nothing is wired into the UI.

**Tech Stack:** Swift 6.1 / SwiftPM, Swift Testing, SwiftTreeSitter 0.25.0 queries, the existing AlloyLSP JSON-RPC client and the scriptable AlloyFakeLSP server.

**Spec:** `docs/superpowers/specs/2026-11-16-editor-essentials-design.md` (Folding section, "Sources (Alloy)", decision 6, and "Approved decisions" at its end).

## Scope

In: spec Folding "Sources (Alloy)" bullets for `IndentFolds`, `AlloyHighlight.foldRanges`, `AlloyLSP/FoldingRange.swift`, and the precedence merge (decision 6). Out: `FoldCoordinator`, `CodeFoldState`, `Workspace+Folds`, gutter chevrons, commands, `ui-state.json` persistence (they need MetalUI G5/G6), the command registry, multi-cursor. The merge is a pure function; the coordinator that calls it is a later branch. No UI changes, so no new frame-guard test lands here; Task 8 re-runs the existing guards to prove they did not move.

## Global Constraints

- Frame guards must not rise: `ViewRerunTests.steadyFrameRequests` 88; `CodeModePerformanceTests.steadyCode1/2/3` 91/107/117; idle frames cost 0 element requests. A hidden or closed feature costs nothing per frame (these sources add no per-frame work).
- Fold ranges are 0-based line numbers. `FoldRange(startLine:endLine:)` hides lines `startLine+1 ... endLine`; the start line stays visible. Valid iff `endLine > startLine`.
- One source per document, never merged: LSP over tree-sitter over indentation (decision 6). A source that answered, even with an empty list, wins; `nil` means "not available".
- Tree-sitter returns `nil` for a windowed (large) document and for a language without a fold query. Folding imports or comments as separate kinds is a non-goal; ranges carry no kind.
- Tabs count as the document's tab width in indentation measurement; blank lines take the next non-blank line's indent.
- If MetalUI lacks an API needed, stop and report a MetalUI gap; do not substitute.
- Tests run only as: from the worktree, `lockf -k <the swift test lock> swift test --no-parallel [--filter X]` (the lock path is given by the orchestrator; never write it into a committed file). Plain `swift build` needs no lock. Known flaky under load, ignore if they fail alone: `OverlapIndexTests.unsavedTypingCostIsBounded`, `ByteCopiesTests.readHoldsOneCopy`, `LSPManagerLinterTests.probeAnswersAreCachedUntilReload`.
- Committed files must contain no local paths, user names, session URLs, bundle ids of the author or personal email addresses (the orchestrator supplies the exact forbidden-pattern list; commit-message trailers are excepted).
- Commit messages end with exactly:
  the two trailer lines the orchestrator supplies (Co-Authored-By, then Claude-Session), verbatim
- The foldingRange call stays in one small function so it can move onto the code-intel branch's generic request kernel.

## Review Focus

1. Windows line endings (`\r\n`) and a file with no trailing newline: indentation must not count `\r` as content or indent, and the last line must be measured (Task 2 tests).
2. Empty document, one-line document, all-blank document: no ranges, no crash (Task 2).
3. An edit batch whose rows disagree with the snapshot, or a whole-buffer replace: the cache falls back to a full re-measure instead of reading stale rows (Task 3).
4. A server that answers ranges past the end of the document, with `endLine <= startLine`, duplicates, or overlapping starts: ranges are clamped, dropped or deduplicated, never passed through (Task 6/7).
5. A tree with syntax errors (half-typed code): the fold query still returns ranges for the well-formed parts and never throws (Task 4).

### Task 2: IndentFolds full derivation

**Files:**
- Create: `Sources/AlloyCore/Folding/IndentFolds.swift`
- Test: `Tests/AlloyCoreTests/IndentFoldsTests.swift`

**Interfaces:**
- Consumes: `FoldRange`, `FoldMerge.normalized` (Task 1); `CodeSnapshot` (`lineCount`, `lineRange(_:)`, `byte(at:)`) from MetalUICodeBuffer.
- Produces:
  - `public struct IndentFolds: Sendable` with `public init(snapshot: CodeSnapshot, tabWidth: Int = 4)`, `public mutating func ranges(in snapshot: CodeSnapshot) -> [FoldRange]`.
  - internal `private(set) var measuredLineCount: Int` (cumulative lines measured; test observability, used in Task 3).
  - cache: `[Int16]` indent per line with two reserved values, `blank = -1` and `dirty = Int16.min`.

- [ ] **Step 1: Write failing tests** (build a snapshot with `CodeBuffer(text).snapshot()`; a helper `folds(_ text: String) -> [FoldRange]`):
  - `nestedBlocks`: `"a\n  b\n    c\n    d\n  e\nf\n"` gives `[r(0,4), r(1,3)]`.
  - `blankLinesTakeNextNonBlankIndent`: `"a\n  b\n\n  c\nd\n"` gives `[r(0,3)]` (blank inside the block does not split it) and the trailing blank lines before a dedent are not part of the range: `"a\n  b\n\n\nd\n"` gives `[r(0,1)]`.
  - `tabsCountAsTabWidth`: `"a\n\tb\n\t\tc\nd\n"` gives `[r(0,2), r(1,2)]`; with a width-2 `IndentFolds(snapshot:tabWidth: 2)` identical; `"a\n  b\n\tc\n"` with width 2 treats the tab line as indent 2, so `[r(0,2)]`.
  - `crlfLinesAreNotIndented`: `"a\r\n  b\r\n  c\r\nd\r\n"` gives `[r(0,2)]`; a `"\r\n"`-only line is blank.
  - `noTrailingNewline`: `"a\n  b"` gives `[r(0,1)]`.
  - `emptyOneLineAndAllBlankDocuments`: `""`, `"a"`, `"\n\n  \n"` give `[]`.
  - `dedentToDeeperThanOpener`: `"a\n    b\n  c\nd\n"` gives `[r(0,2)]` (the `c` line closes b's group but still belongs to a's).
- [ ] **Step 2: Run** `--filter IndentFoldsTests`. Expected: FAIL, type not defined.
- [ ] **Step 3: Implement.** Measuring a line: walk `byte(at:)` from the line start, summing spaces (1) and tabs (`tabWidth`) until a non-space/tab byte; a line is blank when it hits `\n`, `\r` or the line end first; cap at `Int16.max`. Derivation: a single pass over lines, skipping blanks, keeping a stack of `(line, indent)`; on each non-blank line with indent `d`, pop while `top.indent >= d` and emit `(top.line, lastNonBlank)` if `lastNonBlank > top.line`, then push; at the end pop everything against the last non-blank line. Pass the result through `FoldMerge.normalized(_, lineCount:)`. `ranges(in:)` measures every `dirty` row first (all rows dirty after `init`), incrementing `measuredLineCount` per row.
- [ ] **Step 4: Run** `--filter IndentFoldsTests`. Expected: PASS.
