# Command registry and command palette Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One shared command registry that generates Alloy's menus, hidden global keys and a command palette (⇧⌘P), with user key overrides resolved through a `Keymap`.

**Architecture:** UI-free value types (`KeyChord`, `Keymap`, `CommandDescriptor`) live in AlloyCore. An app-wide `@MainActor @Observable CommandRegistry` plus a `CommandCenter` (registry, palette model, quick-open model, keymap) live in AlloyKit. `alloyCommands` and `GlobalKeys` become loops over the registry; the palette is a separate component that reads nothing in `AlloyScreen`'s body. Menus, ids and behaviour stay identical to today, proven by a parity test.

**Tech Stack:** Swift 6.1, SwiftPM, MetalUI (read-only, sibling package), Swift Testing.

**Spec:** `docs/superpowers/specs/2026-11-16-command-palette-design.md` (primary, read "Approved decisions" at its end) and `docs/superpowers/specs/2026-11-16-editor-essentials-design.md`, section "Command registry" and "Keybindings" persistence. Where they differ, the palette spec's command model wins and the chord and override fields are added to it.

- Accessibility id on every interactive view; every existing menu and `global-key-*` id is kept. Zero warnings.

- Not in scope: keyboard settings UI, multi-cursor, folding, plugin loading.

## Review Focus

Failure modes the spec implies; each has a test in the owning task.

1. A command id registered twice, or two commands on one default chord (Task 3).
2. A `keybindings` override naming an unknown id, a malformed chord, or `"none"` (Tasks 2, 5): unknown ids are kept and ignored, a malformed chord falls back to the default, `"none"` unbinds; none of these crash or corrupt the settings file.
3. A disabled command invoked from a key, a menu or a stale palette row does nothing (Tasks 3, 5, 6).
4. Palette query with non-ASCII, empty, or very long text, and a result with zero matches (Tasks 1, 6).
5. A plugin that unregisters while the palette is open, or inside its own `run` (Tasks 3, 6, 8).
