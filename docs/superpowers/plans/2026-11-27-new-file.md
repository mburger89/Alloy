# New File Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** File › New File (⌘N) opens an empty Untitled tab. The first Save asks where to put it. Closing or quitting with
text in an Untitled tab asks Save… / Don't Save / Cancel.

**Architecture:**
- An Untitled document lives in `Workspace.documents` and the tab lists under a reserved key, `untitled:<n>`.
  Membership in `Workspace.untitled: Set<String>` is the only test for "is Untitled". The string shape is never parsed.
- Every file-backed service skips those keys.
- The first save writes the text to the chosen URL, opens the real file, and replaces the Untitled tab in place, reusing
  the tab move from `Workspace.saveAs`. Then it drops the Untitled document.

**Tech Stack:** Swift 6, MetalUI (`Commands`, `FileDialogs`, `.alert`), Swift Testing.

**Spec:** docs/superpowers/specs/2026-11-27-new-file-design.md

## Global Constraints

- Tab titles: "Untitled", then "Untitled 2", "Untitled 3"… The lowest free number is used. "Untitled" counts as 1.
- Save dialog: default name "Untitled", starting folder `workspace.projectRoot`.
- Prompt copy: title `Save changes to “<title>”?`, message `Your changes will be lost if you don't save them.`, and
  buttons `Save…`, `Don't Save`, `Cancel`.
- ⌘N is `file.new` (menu id `file-new`), first in the File menu. `session.new` moves to ⇧⌘N, keeping its menu id
  `file-new-session`. `ShortcutClashes` reports no new clash.
- An Untitled key never reaches `ui-state.json` (layout or folds), the ledger, git, LSP, autosave, the outside-edit
  watcher, or search.
- Run tests with `swift test --no-parallel --filter …`. `swiftlint --strict` must be clean. Never weaken an assertion or
  raise a timeout or frame guard.
- No MetalUI edits. If `.alert` can't present three buttons, stop and report the gap. Don't build a workaround.

## Review Focus

1. **Typing in an Untitled tab** never triggers a write anywhere (autosave, leaving the tab, focus loss, quit's
   `saveAll`). Task 1: `untitledIsNeverWritten`.
2. **Saving into a folder that already has a tab open** for the same file: the existing tab is not duplicated. The
   Untitled tab becomes it, and the old duplicate tab goes. Task 2: `saveUntitledOverAnOpenFile`.
3. **Two Untitled tabs, close the first, ⌘N again** reuses "Untitled" (the lowest free number). Task 1:
   `numberingReusesTheLowestFree`.
4. **Quit with two non-empty Untitled tabs:** Cancel on the second stops the quit, and the first's choice still applies.
   Task 3: `quitAsksPerUntitledTabAndCancelStops`.
5. **An Untitled tab in a split** (a second group): save replaces it in its own group, not the focused one. Task 2:
   `saveUntitledInSecondGroup`.

  Untitled keys.
- `close(path)` on an Untitled key removes it with no write. Task 3's prompt runs before this is called.

### Task 2: New File command and first save

**Files:**
- Modify:
  - `Sources/AlloyKit/Commands/BuiltinCommands.swift` (`file.new`, the `session.new` chord, and `file.save` and
    `file.saveAs` on Untitled tabs).
  - `Sources/AlloyCore/Model/Workspace+Panes.swift` (factor the in-place tab replacement out of `saveAs`).
- Test: `Tests/AlloyKitTests/NewFileTests.swift`.

**Interfaces:**
- `func replaceTab(_ old: String, with new: String, in pane: PaneID) async` opens `new`. If `new` already had a tab in
  `pane`, that tab is removed. The new tab is placed at `old`'s index, `old` is closed, and `new` becomes active.
  `saveAs` uses it.
- `public func saveUntitled(_ key: String, to target: URL, in pane: PaneID) async throws -> URL?`
  - It writes the buffer text atomically to `target`.
  - Inside the project, it calls `replaceTab(key, with: relative, in: pane)` and returns nil.
  - Outside the project, it closes the key and returns `target`, which the caller passes to `center.openOutsideProject`.
  - A write error throws and changes nothing.
- `file.new`:
  - Title "New File", chord ⌘N, binding `.menu`, menu `.file`, placed first, menu id `file-new`.
  - Enabled when a workspace is open.
  - It calls `newUntitled(in: focused group)`. In Chat mode it switches to the code view first, the same way Open… does.
- `session.new` keeps its id and menu id, with chord ⇧⌘N.
- `file.save` and `file.saveAs` on an Untitled active tab call `center.chooseSaveURL("Untitled", projectRoot)`, then
  `saveUntitled`. Cancel does nothing. The pane is the one holding the tab.

### Task 3: Save / Don't Save / Cancel on close and quit

**Files:**
- Modify:
  - The tab-close entry points (`closeActiveTab`, the tab strip's X, and `tab.close`).
  - `Sources/AlloyKit/LauncherView.swift` (`shutdownRequested`, which already defers a quit with `.later` behind
    `quitPrompt`).
  - The view that presents `quitPrompt`, which also presents the new prompt.
- Test: `Tests/AlloyKitTests/UntitledPromptTests.swift`.

**Interfaces:**
- An observable `untitledPrompt: UntitledPrompt?` holds `key`, `title` and a continuation
  `(UntitledChoice) -> Void`, where `enum UntitledChoice { case save, discard, cancel }`. It lives on the model that owns
  `quitPrompt`, or the workspace if that's cleaner, and is presented with MetalUI `.alert` using the Global Constraints
  copy.
- Closing an Untitled tab with non-empty text asks:
  - `save` runs the first-save flow. If the dialog is cancelled, the close is cancelled.
  - `discard` calls `discardUntitled`.
  - `cancel` keeps the tab.
- An empty Untitled tab closes with no prompt.
- Quit and window close ask once per non-empty Untitled tab, in tab order across groups, before the existing
  busy-terminal check and `beginShutdown`. Any `cancel`, or a cancelled save dialog, replies `false` to every pending
  reply, as the busy-terminal "No" does.

  - `quitWithSavedChoicesProceeds`: one typed tab, answered `save` with a stub URL. The file is written and shutdown
