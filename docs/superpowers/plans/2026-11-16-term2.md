# Terminal sessions and manager (AlloyTerminal target) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real shells behind the existing terminal panel: tabs and lazily restored cwds spawn a pty-backed `TerminalSession` through a `TerminalManager`, with shutdown, busy detection and quit confirmation wired to the existing hooks. The pane view stays the placeholder.

**Architecture:** A new UI-free SwiftPM target `AlloyTerminal` (depends on `AlloyCore` and MetalUI's `MetalUITerminal` product) holds a `PtyHandle`/`PtySpawner` seam (live conformance wraps `PseudoTerminal`; a scripted fake lives in `AlloyTestSupport`), a pure launch planner (shell, env, cwd), `TerminalSession` (one pty + one `TerminalEmulator`, fed on one shared serial reader queue) and `@MainActor TerminalManager`. `TerminalPanelStore` in AlloyKit owns the manager, installs it once per window through the existing `terminalHooksOwner` guard, and a new `Workspace.onTerminalLayoutChanged` hook makes layout changes (toggle, new tab, select, split, lazy restore) spawn `TerminalLayout.panesToSpawn()`.

**Tech Stack:** Swift 6.1, SwiftPM, MetalUI `MetalUITerminal` (read-only), Swift Testing, `MetalUITesting` `TestWindow`.

**Spec:** `docs/superpowers/specs/2026-11-16-terminal-design.md` (design task 5; "Thread ownership", "Failure modes", calls 4-7 and the "Approved decisions" section are binding).

## Known MetalUI gaps (report, do not substitute)

MetalUI master 0dfd9f13 has the emulator core, screen semantics, `PseudoTerminal` (macOS, Linux) and `SurfaceRedrawTrigger`. Not yet there, and this branch does not work around them:
1. **`TerminalEmulator` resize/reflow** (MetalUI plan item 1.5): no `resize(cols:rows:)`. `TerminalSession.resize` resizes the pty and records the size; the emulator keeps its spawn size until MetalUI lands reflow. One test is `.disabled` with this reason and is enabled by the follow-up that adds a single call.
2. **OSC events** (MetalUI 1.4): `.title`, `.workingDirectory`, `.hyperlink` are declared in `TerminalEvent` but not emitted yet. The session's event dispatch is tested by injecting `TerminalEvent` values; live titles and OSC 7 cwd start flowing when MetalUI emits them, with no Alloy change.
3. **`TerminalSnapshotSource` / snapshot merging** is task 7's concern; the session never calls `publishSnapshot()` (it would discard damage with no consumer). It exposes `outputVersion` and an `onOutput` hook instead.
4. No Windows `PseudoTerminal`.

## Review Focus

1. Output followed by immediate exit (`printf x; exit 3`): the last bytes reach the emulator before `onExit(3)` fires, and exit is reported once. Task 3.
2. A shell that ignores SIGHUP (`trap '' HUP`) with a child in its group: shutdown kills the whole group after the 1 s grace, returns, and a second `shutdown()` or a spawn request after shutdown does nothing. Task 5.
3. Restart or close while the old session still produces output or exits: stale callbacks (title, cwd, exit) from a replaced or closed session must not touch the store (generation token). Task 5.
4. Failure paths: shell path missing or not executable, cwd deleted, spawn throws (`openFailed`): no crash, no retry loop, pane shows exited with a notice, Restart is user-driven. Tasks 2 and 5.
5. Hostile environment and bytes: inherited `LC_ALL=C` or Latin-1 locale, `ALLOY_*` secrets in the parent env, invalid UTF-8 and a lone ESC in output must not wedge the reader or leak variables. Tasks 2 and 3.

### Task 3: `TerminalSession` reading, replies and events

**Files:**
- Create: `Sources/AlloyTerminal/TerminalSession.swift`
- Test: `Tests/AlloyTerminalTests/TerminalSessionTests.swift`

**Interfaces:**
- Produces:
  ```swift
  public final class TerminalSession: @unchecked Sendable {
      public static let readerQueue: DispatchQueue            // one shared serial queue for every pane
      public static let readBudget = 64 * 1024                // bytes per read
      public static let wakeupBudget = 1024 * 1024            // bytes per wakeup
      public struct Callbacks: Sendable {                     // all invoked on the main actor, coalesced
          public var onTitle: @MainActor @Sendable (String) -> Void
          public var onWorkingDirectory: @MainActor @Sendable (String) -> Void
          public var onExit: @MainActor @Sendable (Int32) -> Void   // exited(n) -> n, signaled(s) -> 128 + s
      }
      public init(paneID: UUID, pty: any PtyHandle, size: TerminalSize, scrollback: Int,
                  now: @escaping @Sendable () -> Date = Date.init)
      public func start(_ callbacks: Callbacks)
      public func write(_ bytes: [UInt8])
      public var outputVersion: UInt64 { get }                // bumped once per wakeup that fed bytes
      public var onOutput: (@Sendable () -> Void)? { get set } // called on the reader queue, at most once per wakeup
      public func withEmulator<T: Sendable>(_ body: @escaping @Sendable (TerminalEmulator) -> T) async -> T  // runs on the reader queue
      func apply(_ events: [TerminalEvent])                   // internal, for tests
  }
  ```
- Behavior: `start` installs `pty.onReadable(queue: readerQueue)`. A wakeup loops `read(into:)` with a 64 KiB buffer, `feed`s the emulator on the queue, stops at 1 MiB (the level-triggered source fires again, so other panes interleave) or at 0/-1. After feeding it calls `emulator.drainEvents()`: each `.reply(bytes)` is written to the pty at once (DA/DSR/CPR must not be dropped); `.title` and `.workingDirectory` are stored as latest-wins pending values and delivered by at most one outstanding main-actor hop (a flag, so 1 000 titles in one feed deliver once with the last value); `.bell` and `.hyperlink` are ignored here. Exit: a task awaits `pty.exitStatus`, then posts a block on `readerQueue` that drains the pty to end of file, then hops to the main actor and calls `onExit` exactly once. Bytes are never dropped when nobody is looking (the reader always reads, visible or not).
