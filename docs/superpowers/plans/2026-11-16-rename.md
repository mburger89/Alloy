# Rename Symbol Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename Symbol (F2) through the language server, applied all or nothing across open and closed files, with a rename summary (Keep All / Revert All); and the command palette and Quick Open return keyboard focus to where it was when they close.

**Architecture:** AlloyLSP gets `prepareRename` and `rename` requests on the existing `LSPManager.send` kernel. A new AlloyKit `RenameService` turns the answer into `FileEdits` and hands them to the existing `WorkspaceEditApplier` (which gains the 1,000-file cap). The new-name field and the summary are two presentations of the code view's one text-anchored popover (slot B, shared with hover through `PopoverSlotModel`). `edit.rename` (F2) registers in the shared registry through `addIntel` with a new `IntelCommand.rename`.

**Tech Stack:** Swift 6.1, SwiftPM, MetalUI (read only, master 0327155d: #373 TextField in a popover holds focus, #379 `.restoresFocusOnDismiss()` and popovers returning focus to their presenter), Swift Testing, the `AlloyFakeLSP` scripted server (`replies`, `delayMs`, `error`).

**Spec:** `docs/superpowers/specs/2026-11-16-code-intelligence-design.md`, goal 5 and the Edits section; its "Approved decisions" section is binding (1(a) `Author.user` plus an edit group, 3(b) undo per file plus Revert All). Palette part: `docs/superpowers/specs/2026-11-16-command-palette-design.md`, MetalUI gap 2. This plan covers ONLY rename and the palette/Quick Open focus adoption.

## Review Focus

Each line has its test in the named task.

1. A server whose `prepareRename` answers null or errors ("cannot rename here"): the word fallback must NOT run silently over a keyword; show the server's message, open no field (Task 3, 4).
2. The name typed is empty, unchanged or has leading/trailing whitespace: Return with an empty or unchanged name only closes, a trimmed name is sent (Task 4).
3. Typing in the buffer (or switching tab) while the field is open or the request is in flight: the answer is dropped and nothing applies (Task 3, 4).
4. The server returns edits for a file that is open and dirty, or an edit set with more than 1,000 files, or a resource operation: nothing is applied and the message says why (Task 2, 3).
5. Revert All after the user already edited a renamed file, or after a renamed closed file was opened: the conflict is listed per file, no text is lost (Task 5).
