# Alloy roadmap

Spec: `docs/superpowers/specs/2026-11-07-alloy-design.md`

Alloy is several subsystems, so it is built as a sequence of plans. Each plan yields working, tested software. Only Plans 1 and 2 are written in detail now; each later plan is written when its inputs exist (the protocol facts Plan 1 records, and the MetalUI components it depends on).

| Plan | Scope | Depends on | Status |
|---|---|---|---|
| **1 Foundation** (`2026-11-07-alloy-plan-1-foundation.md`) | Scaffold; Claude Code wire protocol; session hosting; per-session edit ledger with line attribution, Keep and Revert; three-pane app with sidebar, plain chat with in-chat diffs and permission cards, read-only file panel | — | written |
| **2 Benchmark harness** (`2026-11-07-alloy-plan-2-bench.md`) | `alloy-bench`: startup, typing latency, scroll frame times, memory, large-file open, idle CPU for Zed, Delta, Alloy; median and p95; dated JSON results | MetalUI G7 for attribution (optional) | written, runs in parallel with Plan 1 |
| **3 Rich chat** (`2026-11-07-alloy-plan-3-rich-chat.md`) | Color + icon per block type (G3 icons), block markdown (G2), thinking display, slash commands with autocomplete (built-in, custom, skills), plan mode card, AskUserQuestion card, image paste/drop, `@file` mentions, permission-mode and model switching, interrupt and queued messages, resume and history replay from `.jsonl`, per-session cost in sidebar, settings UI (claude path) | Plan 1; MetalUI G2, G3, G6 stick-to-bottom | written |
| **4 Code panel** (`2026-11-07-alloy-plan-4-code-panel.md`) | MetalUI `CodeView` (G1) with tree-sitter highlighting, author gutter, inline and side-by-side diffs (G5), tabs (G4), ⌘P quick-open, the user's own edits as author "You" with ~1 s autosave and the dirty-buffer rule, Keep/Revert in the panel, git-commit baseline reset, outside-edit watcher | Plans 1, 3; MetalUI G1 (done), G4 (stopgap until it lands) | written |
| **5 Coordination and shared knowledge** (5a: `2026-11-09-alloy-plan-5a-shared-knowledge.md`, **implemented 2026-11-09; hands-on check pending with the user**, live check in `docs/protocol-notes-plan5.md`; **5b Coordination (`2026-11-09-alloy-plan-5b-coordination.md`): done 2026-11-09, pending the user's hands-on check**; the live check is in `docs/protocol-notes-plan5.md`; the Coordination items below are 5b) | Shared knowledge first (`specs/2026-11-09-alloy-shared-knowledge-design.md`): fork button and `/fork`, "already read" notes, shared-notes MCP tools with a read index, launch guidance, redundant-read counting, and a Settings view (the gear opens it; holds the Claude path and all app-wide settings, replacing the popover). Then: localhost hook server (PreToolUse/PostToolUse `http` hooks), proposed-change tracking, overlap index (same/adjacent lines, ±3), told-once rule, `additionalContext` notes, Alloy MCP server (`list_sessions_changes`, `send_message`, `claim_region`), cross-session messages via stdin `priority:"next"`, rate limits, tug-of-war detection and back-off message, user notices and ⚠ markers | Plans 1, 3 | after Plan 3 |
| **7 Themes** (spec `docs/superpowers/specs/2026-11-09-alloy-themes-design.md`) | 7a: theme slots, theme files, built-ins (Dracula default, Alloy Dark/Light, Solarized Dark/Light, One Dark), Settings picker (one theme or match system). 7b: `/theme` with Claude theme tools, live preview, contrast check | Plan 5a (Settings view, MCP server) | 7a implemented; hands-on check pending. 7b implemented; hands-on check pending. Next, before Plan 6 (user decision 2026-11-09) |
| **6 Parity and publishing** | Benchmark checkpoints against Zed after Plans 3 and 4; triage each shortfall to Alloy or MetalUI (send MetalUI causes to the MetalUI session); GitHub Pages results page generated from Plan 2's JSON | Plans 2, 4 | Plan 6 (`2026-11-11-alloy-plan-6-parity.md`): checkpoint 2026-11-11 published; 6 of 7 at par or ahead; open shortfalls in `docs/parity.md` (memory with the large file open) |

Plan 2 checkpoint: once Plan 1's file panel opens a file from the command line, `alloy-bench` measures Alloy too, so regressions show up from the start, not only in Plan 6.
