# Code intelligence wave 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Alloy completion as you type (with resolve, commit characters, auto-import edits and plain-text snippets), signature help in the same overlay, and code actions with quick fixes (lightbulb, the code-action list, F8 to a problem then the fix).

**Architecture:** AlloyLSP grows capabilities, three request files (completion, signature help, code actions) on the existing `LSPManager.send` kernel, `workspace/executeCommand`, and an answer for the server's `workspace/applyEdit`. AlloyKit adds an `IntelligenceScheduler` and `IntelligenceOverlayModel` per `OpenDocumentView`; the scheduler exists only while a server offers one of the three features. Completion, signature help and the action list share ONE `suggestionOverlay` (slot A) chained after the hover `popover` (slot B); edits from actions go through the existing `WorkspaceEditApplier`.

**Tech Stack:** Swift 6.1, SwiftPM, MetalUI (read only), Swift Testing, the `AlloyFakeLSP` scripted server (`replies`, `afterRequest`).

**Spec:** `docs/superpowers/specs/2026-11-16-code-intelligence-design.md` (its "Approved decisions" section is binding). This plan covers design goals 1, 2 and 8 and design tasks 7 and 8 only.

## Global Constraints

- Out of scope: rename (waits for MetalUI gap 3), the snippet session (gap 1), named F-keys (gap 5), the text context menu, a problems panel. Completion and signature help open only with a single, empty selection.
- Decision 2(a): snippet items are inserted as PLAIN TEXT: placeholders stripped to their default text, the caret placed at `$0` (else at the end). `snippetSupport` is advertised for that reason.
- MetalUI is read only and never worked around. If an API is missing, or a CLOSED `suggestionOverlay` costs element requests per frame beyond the budget below, STOP and report a MetalUI gap; build no substitute.
- Frame guards on this branch (never raise): Chat `ViewRerunTests.steadyFrameRequests` = 46; Code `CodeModePerformanceTests.steadyCode1/2/3` = 46/62/72; idle frames cost 0 element requests and 0 body reruns. The only tolerated extra is the hover popover's known gap (`HoverGuardTests.knownPopoverGap` = 2), and only for views that attach hover. A closed overlay or lightbulb adds nothing beyond it: a view with completion but no hover capability has a budget of `steady + 0`.
- No cost per keystroke without a capability: no scheduler, Task, timer, observable write or request when `lspOpen` is false, the document is not `.editable`, or no server offers completion, signature help or code actions.
- Overlay state lives in `IntelligenceOverlayModel` (`@Observable`, held by the view as `@ObservationIgnored let`). No view body reads it except the overlay's content closure. It is written only when the visible rows or the selection change, never when a request starts.
- Only the focused pane's view schedules or shows anything; the same file in two panes has two schedulers and only the focused one acts. Never in the old-text pane of side by side.
- Timings: completion debounce 60 ms trailing; trigger characters at once; signature help at once on trigger characters; lightbulb probe 250 ms after a caret move that is not typing and 750 ms after typing stops. Timeouts: completion 2 s, resolve 1 s, signature 2 s, code actions 2 s, `codeAction/resolve` 1 s, `executeCommand` 5 s. Caps: popup 50 rows, doc pane 12 lines, decoded completion items 5,000 (a longer list is cut and treated as `isIncomplete`).
- Order: fuzzy score (`FuzzyMatch.score` on `filterText ?? label`), then `sortText ?? label`, then label. Return and Tab accept; a `textEdit` or `insertReplaceEdit` uses the INSERT range, and must lie on the caret line and contain the caret, else the item replaces the word before the caret with `insertText ?? label`. `additionalTextEdits` that overlap the main edit are dropped (debug log line).
- Accessibility ids: `completion-popup`, `completion-row-<i>`, `completion-doc`, `signature-help`, `code-action-menu`, `code-action-<i>`; menu ids `menu-trigger-completion`, `menu-signature-help`, `menu-quick-fix`. Gutter markers expose no accessibility element in MetalUI, so the lightbulb (spec id `lightbulb`) is asserted through `OpenDocumentView.lightbulbLine` and the gutter click closure; note this in the task report, it is not a blocker.
- All new commands go in the shared registry, `Sources/AlloyKit/Commands/BuiltinCommands.swift` through its local `addIntel` helper, with a new `IntelCommand` case in `Sources/AlloyCore/Editor/IntelHooks.swift` (see `docs/command-registry.md`). New chords: ⌃Space completion, ⌃⇧Space signature help, ⌘. quick fix (`chord(.cmd, ch("."))`). F8 is the existing key handler in `FilePanelView.codeKeyHandlers`; keys the overlay needs (↑ ↓ Return Tab Esc, ⌥↑ ⌥↓) are `onKeyPress` handlers on the `CodeView`, not hidden buttons.
- Theme values only; an accessibility id on every interactive view; zero warnings; never write `~/.claude` or a project's `.claude`.
- Tests run only as `lockf -k <the swift test lock> swift test --no-parallel [--filter X]` (called `TEST` below). `swift build` needs no lock. Known flaky if failing alone under load: `OverlapIndexTests.unsavedTypingCostIsBounded`, `ByteCopiesTests.readHoldsOneCopy`, `LSPManagerLinterTests.probeAnswersAreCachedUntilReload`.
- No subagents, no GUI launches, no broad pkill, no bare `git stash`, no Docker. Committed files contain no home-directory paths, usernames, emails, sandbox temp paths or session URLs. Every commit message ends with exactly the two trailer lines of the task brief (Co-Authored-By Claude Opus 5.5, then Claude-Session).

## Review Focus

Failure modes the spec implies but a task's headline tests would not catch. Each has its test in the named task.

1. Typing fast inside a word while a slow answer is in flight, then the answer lands: it is dropped (buffer version, caret line or word start moved), never shown, never applied at the wrong place. (Tasks 4, 5)
2. Accepting an item after the user typed more of the word, with an auto-import `additionalTextEdit` above and one overlapping the word: the typed letters are replaced, the import lands once, the overlapping one is dropped, one undo step. (Task 4)
3. Non-ASCII text (multi-byte, emoji pairs, CRLF) with UTF-8 and UTF-16 servers: completion ranges, the caret after a snippet's `$0`, signature parameter label offsets (which are UTF-16 offsets into the label) and action edits land on the right bytes. (Tasks 2, 3, 4)
4. A reply of `null`, `[]`, an error, a 5,000-plus item list, or an item with no `label` detail: no popup, no crash, no stuck state; a server that dies with a popup open clears it. (Tasks 2, 3, 5, 7)
5. Code actions of every shape (inline `edit`, `data` only resolved later, `command` only followed by `workspace/applyEdit`, `edit` plus `command`, `disabled`, a command the server did not list) from the main server and a linter at once, and a stale or conflicting edit: nothing applied, a message shown, the group revertable. (Tasks 6, 7)
6. Multiple carets, a selection, read-only documents, the old-text pane, a tab switch or a focus change with an overlay open: no popup opens, an open one closes, no probe runs. (Tasks 5, 7)
