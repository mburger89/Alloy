# Release app fixes (Track A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the app, packaging, notices and test issues from Track A (A1-A11) of the release-readiness spec, on branch `fix/release-app`.

**Architecture:** Small, local changes in `AlloyCore` (launch, settings, file index, launch configuration), `AlloyLSP` (locator), `AlloyKit` (chat failure row, menu) and the packaging scripts. Each risky behaviour goes behind an injected seam so tests never touch the real Keychain, real Application Support or `~/.claude`.

**Tech Stack:** Swift 6 / SwiftPM, MetalUI, Swift Testing, POSIX shell (`bundle-macos.sh`, `release-macos.sh`), `sips`/`tiffutil`.

**Spec:** `docs/superpowers/specs/2026-11-19-release-readiness.md` (Track A; read "Approved decisions" at its end). Track B (README, site, SECURITY.md, release notes) is another branch: do not touch it.

## Global Constraints

- Run tests only as: the swift test lock around `swift test --no-parallel [--filter X]` (`lockf -k <lockfile> swift test ...`; the orchestrator gives the lockfile path). Plain `swift build` needs no lock. Run `release-macos.sh 0.1.0 --dry-run` under the same lock.
- Frame guards must not rise and no constant or timing limit may be raised: `ViewRerunTests.steadyFrameRequests` 88; `CodeModePerformanceTests.steadyCode1/2/3` 91/107/117; chat 46; code 46/62/72; knownPopoverGap 0; steadyCompare 77; terminal 0/0/55; idle frames 0 element requests. A hidden or closed feature costs nothing per frame.
- Known flaky under load only: `OverlapIndexTests.unsavedTypingCostIsBounded`, `LSPManagerLinterTests.probeAnswersAreCachedUntilReload`, `ByteCopiesTests.readHoldsOneCopy` (the last is fixed in Task 7).
- If MetalUI lacks an API: stop and report a MetalUI gap; no workaround. `../MetalUI` is read-only.
- No new network calls, no telemetry. No subagents, no GUI launches, no broad `pkill`, no bare `git stash`, no writes to `~/.claude` or the project `.claude`, no Docker.
- Tests must not touch the real login Keychain, the real Application Support `Alloy` folder or `~/.claude`; use temp dirs and `ALLOY_DATA_DIR`-style injection.
- Committed files contain no local paths or personal data (no home-directory paths, no scratch-directory paths, no session URLs, no personal bundle ids or email addresses; the orchestrator's check pattern is the one to grep with), except commit-message trailers. This includes `THIRD-PARTY-NOTICES.md` and test fixtures. Note the spec's copyright line contains the licence holder's name by design (it is the LICENSE holder); keep it exactly as the spec gives it.
- Claude sessions behave identically apart from A1 (visible failure) and A5 (JSON passed as 0600 file paths): same flags, same order.
- Every commit message ends with the two trailer lines the orchestrator gave (Co-Authored-By Claude Opus 5.5, then Claude-Session). They appear only in commit messages, never in files.

## Review Focus

- A failed launch whose message is very long or empty: the chat row must wrap and still show a hint (Task 1 test).
- Retrying a failed session twice quickly, or while shutting down: one launch only, no duplicate notice (Task 1 test).
- `settings.json` that is valid JSON of the wrong shape (an array), and a corrupt file whose `.corrupt-<timestamp>` name already exists: moved aside without overwriting, defaults not saved over the original (Task 2 tests).
- Support directory that already exists with looser permissions (0755) or is a symlink: tightened to 0700 and never followed outside (Task 2 test for the existing-dir case).
- Session directory leftovers from a crashed run, and two sessions ending in either order: only that session's files go, sibling sessions' files stay (Task 3 tests).
- `bundle-macos.sh` run twice, or a binary with no matching rpath: the rpath strip is idempotent and does not fail (Task 5 script test).

(Each line has its pinning test in the owning task below.)
