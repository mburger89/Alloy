# Menu Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the basic keyboard commands in the menu bar, and add File › Open… on ⌘O.

**Architecture:**
- New `MenuPlacement` cases `.file`, `.find` and `.window`, filled by `alloyCommands` from the registry.
- Commands that move into a menu switch from `.global`/`.globalInCode` to `.menu` binding.
- Open… is a new registry command. It asks an injected file chooser for URLs and opens each one the way `alloy <file>`
  does.

**Tech Stack:** Swift 6, MetalUI `Commands` (`CommandGroup`, `CommandMenu`, `Menu`) and `FileDialogs`, Swift Testing.

**Spec:** docs/superpowers/specs/2026-11-26-menu-bar-design.md

## Global Constraints

- The menu titles and shortcuts are exactly as in the spec's Layout.
- One owner per chord: no command keeps a hidden global key once its menu item exists.
- Keymap overrides and unbinding still apply to menu items (`registryMenuItem` already does this).
- **Out of scope until MetalUI ships `.saveItem`:** Close Tab, Close Window, Save, Save As and Save All. Don't move ⌘S or
  ⌘W.
- `ShortcutClashes` must report no new clash.
- Run UI tests with `swift test --no-parallel`.
- `swiftlint --strict` must be clean.
- Never weaken an assertion, raise a timeout or raise a frame guard.

## Review Focus

1. ⌘N in Chat mode: the sidebar's New Session button used to own it. After this there is exactly one handler, and ⌘N
   still makes one session, not two. Task 1.
2. ⌃Tab and ⌘1–9 while a terminal is focused still act on terminal tabs, as the global closures do today. Task 1.
3. ⌘F while the terminal is focused still opens the terminal's find (`terminal.find`), not the editor's. Task 2.
4. Open… with Cancel does nothing. Choosing several files opens all of them. A file outside the project opens like
   `alloy <file>`. Task 3.
5. The frame element count drops, or at least does not grow, once the hidden global keys are removed. CodeModePerformance
   and frame-guard tests hold. Task 1.

### Task 3: File › Open… (⌘O)

**Files:**
- Modify: `BuiltinCommands.swift`, and the place that constructs the builtins, to inject the chooser.
- Find the `alloy <file>` open path, starting from `Sources/Alloy/main.swift` and the RPC/launcher, and reuse it.
- Test: `Tests/AlloyKitTests/OpenFileCommandTests.swift`.

**Interfaces:**
- `file.open`: title "Open…", category `.file`, shortcut ⌘O, binding `.menu`, menu `.file`, placed after New Terminal
  Tab. It is enabled when a workspace is open.
- The chooser is injected as `chooseFiles: @MainActor () async -> [URL]`. In production it calls
  `FileDialogs.openFiles(allowedContentTypes: [], allowsMultipleSelection: true)` on the key window, and errors are
  treated as `[]`.
- Each URL inside the project calls `workspace.open(relativePath)`. Each URL outside the project goes through the same
  call `alloy <file>` uses.
