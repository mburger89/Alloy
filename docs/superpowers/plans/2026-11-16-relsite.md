# Release Docs and Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the written material for the 0.1.0 release correct and user-facing: release notes, README, SECURITY.md, issue templates, and the landing site.

**Architecture:** Text and copy only. Facts are checked against the code first and recorded in the commit that uses them. Site copy lives in `LandingContent` (strings) and `LandingPage` (markup); `Bench/site` is regenerated by the existing `site` command and committed.

**Tech Stack:** Markdown, GitHub issue forms (YAML), Swift 6 (Bench package, swift-testing).

**Spec:** `docs/superpowers/specs/2026-11-19-release-readiness.md`, Track B (items 1-4) and "Approved decisions". Track A (Sources/, Packaging/) is another branch: do not touch it. `THIRD-PARTY-NOTICES.md` is added there; this branch only links to it.

## Global Constraints

- Only files under `docs/`, `README.md`, `SECURITY.md`, `.github/ISSUE_TEMPLATE/`, `Bench/Sources/BenchCore/Landing*.swift`, `Bench/Tests/`, `Bench/site/`. Never `Sources/`, `Packaging/`, `../MetalUI`.
- Style: plain, user-facing, no hype, short sentences. No internal names: no task or plan numbers, no "MetalUI gap" jargon, no session ids, no merge hashes.
- Committed files must not contain local paths, session ids, bundle ids with the author's name, or personal email (the privacy pattern the orchestrator gave; keep it in a local shell variable `PRIV`, never in a committed file). Public repo URLs under `github.com/mburger89/Alloy` do not match it and are allowed.
- Claude Code stays the lead and first-class. Other agents (Codex, Gemini CLI, OpenCode, Goose, custom ACP agents) are a headline benefit, not a replacement.
- Requirements: Apple silicon only, macOS 14 or later (`LSMinimumSystemVersion` is 14.0 in `Packaging/macOS/Info.plist`; `scripts/bundle-macos.sh` builds `--arch arm64`).
- Privacy wording (README, site, notes): no telemetry and no account; the only requests Alloy itself makes are update checks; agents and language servers you run make their own connections.
- Site: keep structure, benchmark numbers and screenshots. `downloadAvailable` stays `false`; the "Coming soon" state is unchanged.
- Run tests only as: `cd <worktree> && lockf -k <swift test lock file> swift test --no-parallel [--filter X]`, and for Bench `lockf -k <swift test lock file> swift test --package-path Bench`. No GUI apps. No subagents.
- Frame guards (chat 46; code 46/62/72; steadyFrameRequests 88; steadyCode 91/107/117; idle 0) cannot move because no `Sources/` file changes. Task 4 confirms with `git diff --stat master -- Sources Packaging` being empty.
