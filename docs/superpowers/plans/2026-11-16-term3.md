# Terminal output half (TerminalView in the panel) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the placeholder pane with MetalUI's `TerminalView`, driven by each pane's `TerminalSession` through a `TerminalSnapshotSource`, with palette, font, cursor, resize, focus, command retargeting, titles, cwd and notices wired, and the exited Close/Restart overlay kept.

**Architecture:** `TerminalSession` (AlloyTerminal) hands its emulator to a `TerminalSnapshotSource` and reads the pty into `source.feed`; replies and OSC events come back through the source's `onReply` / `onEvents`. A pure `TerminalAppearance` value (AlloyKit) turns theme tokens plus `TerminalSettings` into MetalUI's `TerminalPalette`, a font and the blink flags. `TerminalPaneView` (replaces `TerminalPlaceholderPane`) builds the `TerminalView` for a running pane and the overlay for an exited one. Focus is reported to `TerminalPanelStore`, which feeds a small action table on `Workspace` that the ⌘W / ⌘T / ⌃Tab commands consult.

**Tech Stack:** Swift 6.1, SwiftPM, MetalUI `MetalUITerminal` and `MetalUITerminalUI` (read-only), Swift Testing, `MetalUITesting` `TestWindow`.

**Spec:** `docs/superpowers/specs/2026-11-16-terminal-design.md` (design task 7, output half; the "Approved decisions" section is binding, in particular 3(a): ⌘W/⌘T/⌃Tab act on terminal tabs while a terminal is focused, and "the v1 background is opaque").

## MetalUI gaps (report, do not substitute)

1. **Default cursor shape.** `TerminalView` has no cursor-shape parameter: the shape (block, bar, underline) comes only from the program's `CSI n SP q`, and the emulator's initial style is block. `TerminalSettings.cursorStyle` therefore cannot be applied. Do NOT feed a synthetic `CSI n SP q`. Wire `cursorBlink` only, leave `cursorStyle` unapplied, and report this gap in the final message (Task 7 writes it into the plan's status note and the settings footer stays as is).
2. **Surface replay (#362).** A keystroke frame with a visible terminal costs +2 element requests until it merges (`knownVisibleTerminalGap`).
3. **Descendant focus (possible).** Task 4 starts with a spike on whether a `@FocusState` on the pane wrapper observes the `TerminalView`'s own focusable leaf. If it does not, report a gap; do not poll or fake focus.

## Review Focus

- A pane that exits while its view is mounted: overlay replaces the view, no resize or draw after exit, Restart returns a fresh view bound to the new session's source (Task 3).
- Restart / close / tab switch re-binds a different `TerminalSnapshotSource`: a view must never be bound to a retired session's source, and one source never feeds two views (Task 3).
- Resize storms (window drag) coalesce: many `onResize` calls reach the pty as the newest size, never below 2 x 1 (Task 1, 3).
- A pane with no session yet (lazy restore, spawn failure): no view, no crash, notice shown (Task 3).
- Unicode/OSC garbage in titles and cwd (empty, 1000 chars, repeated): at most one rerun, capped at 256 (Task 6).
- ⌘W on the last terminal tab hides the panel and returns focus to the editor; ⌘W with an editor focused still closes the editor tab (Task 5).

## Status

Output half of terminal design task 7 is complete. Open MetalUI items:

1. **Default cursor shape (gap, open).** `TerminalView` has no cursor-shape parameter, so `TerminalSettings.cursorStyle` is not applied; only `cursorBlink` is wired. The shape comes from the program's `CSI n SP q`.
2. **Surface replay (#362, resolved).** MetalUI merged it; `knownVisibleTerminalGap` and `knownTerminalViewExcess` are both 0 in `TerminalGuardTests`. A visible terminal adds no element requests to an editor keystroke frame.
3. **Descendant focus (partly resolved, gap open).** MetalUI #366 (focus-within) makes `.focused` on the non-focusable pane wrapper read the `TerminalView`'s focus, and `TerminalPanelStore.paneDidChangeFocus` consumes it. But since MetalUI 5.4 (ca16df79, at 9cccde0a) a pointer press does not focus a `TerminalView` (its press is "the view's own" and it registers none), and the surface is not an accessibility element, so no click or `TestWindow.focus` reaches it. The wrapper therefore never reads true from a click; only Tab or a programmatic write focuses a terminal. `TerminalPaneTests.clickingAPaneFocusesIt` records this as a known issue (it fails once MetalUI fixes it); the other focus tests drive `paneDidChangeFocus` directly. Report to MetalUI: a press on a `TerminalView` should focus it.

Seams for the input half (MetalUI 5.4 / 5.5, parameters currently inert): the single `TerminalView(...)` call in `Sources/AlloyKit/Terminal/TerminalPaneView.swift` carries `onInput` (keyboard, IME, paste) and `onLink`; selection, find and mouse reporting plug in there too.
