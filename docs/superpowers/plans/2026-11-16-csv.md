# CSV Table View (Phases 1 and 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CSV and TSV files in Code mode get a Text | Table switch; Table is a read-mostly checking view (row numbers, header, tints by author, deletion markers, view-only sort, row selection, Previous/Next change, row-level Keep and Revert) over the same open document.

**Architecture:** AlloyCore gets a UI-free CSV layer: `CSVDialect`, a lenient field parser and encoder, a compact `CSVIndex` of row start offsets with incremental updates, and an ownership helper over `FileLedger.runs()`. AlloyKit gets `Presentation.table` and a `TablePanel` on MetalUI `Table` (virtualised, 24 pt rows, `.equatable()` cells) that parses only visible rows from snapshot ranges into a bounded window cache. Nothing in the table runs per frame when idle.

**Tech Stack:** Swift, SwiftPM, MetalUI (`Table`, `TableColumn`, `TableColumnForEach`, `tableFrozenColumns`, `tableRowIndex`, `sortOrder`, `ScrollViewReader.scrollTo(rowID)`; MetalUI master includes Table PR C, read-only for us), `MetalUICodeBuffer` (`CodeBuffer`, `CodeSnapshot`, `CodeEditCursor`, `buffer.map`).

**Spec:** `docs/superpowers/specs/2026-11-20-csv-table-design.md`. This plan covers Phases 1 and 2 only. Out of scope: cell selection, inline cell editing, cell-level keep/revert, whole-cell tints, Table as the default (all Phase 3, needs MetalUI PR F, not merged). If a task needs a MetalUI API that is missing, stop and report a MetalUI gap; build no substitute.

## Global Constraints

- Frame guards must not rise, and no constant or timing limit is raised: `ViewRerunTests.steadyFrameRequests` (88) and `CodeModePerformanceTests.steadyCode1/2/3` (91/107/117) stay exactly as they are in the tree (the chat 46 and code 46/62/72 figures in the spec are the same guards in earlier units); `knownPopoverGap` 0; `steadyCompare` 77; terminal 0/0/55; idle 0 element requests. A hidden or closed Table costs nothing per frame; an idle Table costs 0.
- Single-copy rule: never hold a second full copy of the file (`ByteCopiesTests`). Parse visible rows from `snapshot.utf8(in:)`. The index is `[UInt32]` row starts plus a few small side sets; the window cache is bounded.
- Offsets are UTF-8 bytes. Rows may span lines. The row terminator (LF, CRLF, mixed) belongs to the row, never to a cell. A leading UTF-8 BOM is skipped and kept.
- Buffer edits from Table (row revert) go through `doc.buffer.transaction { replace(range, with:) }` with origin `.programmatic`. Read-only documents (`doc.state != .editable`) never offer Keep/Revert.
- Lenient quoting (spec section 2) applies equally to `.csv` and `.tsv`. Rows parsed by a fallback are flagged.
- MetalUI is read-only. Never launch GUI apps. Tests never touch the real Application Support/Alloy directory, `~/.claude`, or the login Keychain (use the existing test rigs and temp dirs).
- Run tests only through the swift test lock with `swift test --no-parallel [--filter X]` from the worktree; plain `swift build` needs no lock. Known flaky under load only: `OverlapIndexTests.unsavedTypingCostIsBounded`, `ByteCopiesTests.readHoldsOneCopy`, `LSPManagerLinterTests.probeAnswersAreCachedUntilReload`.
- Committed files contain no local paths or personal data. Commit messages end with exactly:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and the `Claude-Session:` trailer the orchestrator supplies.

## Review Focus

Inputs the spec implies that no explicit test line covers; each is pinned in the task named.

1. A CSV with a single stray quote near the top of a 10 MB file must not swallow the file or hang the index build (Task 1, Task 2).
2. An empty file, a file of only a BOM, a file with only a header, and a file with no trailing newline show a sane table (zero rows, no crash, last row complete) (Task 2, Task 4).
3. An agent rewrite that deletes every row, or one that changes the delimiter, leaves Table consistent (no stale rows, no out-of-range reads) (Task 3).
4. A sorted table whose rows shift under an agent edit never shows the wrong row's values for a row id (frozen order maps by file ordinal; dropped rows vanish) (Task 6).
5. Previous/Next on a file with zero changes does nothing and does not crash; with unsaved user typing before a changed row, the row still lands on the right ordinal (Task 7).

### Task 1: Dialect, lenient parser and encoder

**Files:**
- Create: `Sources/AlloyCore/CSV/CSVDialect.swift`, `CSVParser.swift`, `CSVEncoder.swift`
- Test: `Tests/AlloyCoreTests/CSVParserTests.swift`, `CSVEncoderTests.swift`

**Interfaces:**
- Produces:
  - `public struct CSVDialect: Equatable, Sendable { public var delimiter: UInt8; public static func detect(language: String?, firstRow: [UInt8]) -> CSVDialect }`. `tsv` gives tab; `csv` gives `,` unless the first logical row has more `;` than `,` outside quotes.
  - `public struct CSVRowParse: Equatable, Sendable { public var fields: [Range<Int>]` (field byte ranges relative to the row start, quotes included) `; public var quoted: [Bool]; public var terminatorLength: Int; public var flagged: Bool }`.
  - `public enum CSVParser { public static func parseRow(_ bytes: [UInt8], dialect: CSVDialect, lookahead: CSVLookahead) -> CSVRowParse; public static func value(of field: ArraySlice<UInt8>, quoted: Bool) -> String; public static func displayValue(...) -> String }` where `value` unquotes and un-doubles, and the display form shows only the first line plus a trailing `\u{23CE}` when the value contains CR or LF.
  - `public struct CSVLookahead: Sendable { var maxBytes = 1 << 20; var maxLines = 10_000 }`.
  - `public enum CSVByteSource` protocol surface: `public protocol CSVBytes: Sendable { var utf8Count: Int { get }; func utf8(in: Range<Int>) -> [UInt8] }`, with `extension CodeSnapshot: CSVBytes` (use the existing members) and a `[UInt8]` conformance for tests.
  - `public enum CSVRowScanner { public static func nextRow(in: some CSVBytes, from: Int, dialect: CSVDialect, lookahead: CSVLookahead) -> (end: Int, flagged: Bool) }` reads in 64 KB chunks and returns the offset after the row terminator.
  - `public enum CSVEncoder { public static func encode(_ value: String, delimiter: UInt8, wasQuoted: Bool) -> [UInt8] }`.

- [ ] **Step 1: Write the failing tests** (`CSVParserTests`). One test per corpus item, with exact expected values:
  - `plainRow`: `a,b,c\n` gives 3 fields, terminator 1. `crlf` terminator 2; `lastRowNoNewline` terminator 0; mixed LF/CRLF rows keep their own lengths.
  - `quotedDelimiterAndNewline`: `"a,b","line1\nline2",c\n` is one row of 3 fields, `value` of field 0 is `a,b`, field 1 is `line1\nline2`; `displayValue` of field 1 is `line1\u{23CE}`.
  - `doubledQuotes`: `"say ""hi"""` value is `say "hi"`.
  - `emptyFieldsAndRagged`: `,,\n` gives 3 empty fields; a 2-field row is not padded by the parser.
  - `bomIsSkippedByIndexNotParser` is covered in Task 2; here assert `CSVDialect.detect` ignores a BOM in `firstRow`.
  - `semicolonDetected`: `a;b;c` with `language: "csv"` gives `;`; `"a,b";c` (comma inside quotes) stays `;`; `language: "tsv"` is always tab.
  - Lenient: `strayQuoteMidFieldIsLiteral` (`ab"c,d` is 2 fields, not flagged); `quoteOpensOnlyAtFieldStart`; `unmatchedOpeningQuoteFallsBack` (`"abc,def\nnext,row\n` with no closing quote anywhere: first row is `"abc` and `def`, flagged, and the scanner returns the first newline as the row end, so `next,row` is a separate row); `closingQuoteNotFollowedByDelimiterFlags` (`"ab"c,d`); `lookaheadBoundRespected` (1 MB source of one unmatched opening quote returns promptly with the first line as the row, flagged; use a small `CSVLookahead(maxBytes: 100, maxLines: 3)` in the test to keep it fast); `tsvFollowsTheSameRules`.
- [ ] **Step 2: Write the failing encoder tests** (`CSVEncoderTests`): `needsQuotesForDelimiterQuoteCRLFAndEdgeSpaces`; `keepsQuotingWhenWasQuoted` (`abc` with `wasQuoted: true` gives `"abc"`); `doublesQuotes`; round trip over a fixed table of 30 awkward strings: `value(of: encode(v)) == v` for both delimiters.
- [ ] **Step 3: Run to verify failure.** Run (via the swift test lock): `swift test --no-parallel --filter CSV`. Expected: compile errors, types undefined.
- [ ] **Step 4: Implement** the types above. `parseRow` and `nextRow` share one state machine (do not write the quote rules twice); `nextRow` finds the row end, then `parseRow` runs on that row's bytes only. The fallback to a literal quote, when the closing quote is not found within `lookahead`, flags the row.
- [ ] **Step 5: Run the CSV filter; expect PASS.**
- [ ] **Step 6: Commit** `feat(csv): dialect, lenient parser and field encoder`.

**Files:**
- Create: `Sources/AlloyCore/CSV/CSVIndex.swift`
- Test: `Tests/AlloyCoreTests/CSVIndexTests.swift`, `CSVIndexPropertyTests.swift`

**Interfaces:**
- Consumes: `CSVBytes`, `CSVRowScanner`, `CSVDialect`, `CSVLookahead` (Task 1); `CodeEdit` (pre-edit UTF-8 range via its start/old-end offsets, `newText` byte length) from `MetalUICodeBuffer`.
- Produces:
  - `public struct CSVIndex: Equatable, Sendable` with `rowStarts: [UInt32]`, `flaggedRows: [UInt32]` (sorted row numbers), `bomLength: Int`, `byteCount: Int`, `dialect`.
  - `public var rowCount: Int`; `public func rowRange(_ row: Int) -> Range<Int>` (terminator included); `public func row(containing offset: Int) -> Int` (binary search; clamps); `public func isFlagged(_ row: Int) -> Bool`.
