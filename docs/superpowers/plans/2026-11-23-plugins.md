# Alloy Plugins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plugins for Alloy: one `alloy-plugin.json` manifest covering a no-code tier (themes, language-server configs, settings, task commands) and a scripted tier (an out-of-process JSON-RPC child that adds commands, decorations, panels, events, project access, state and MCP tools), installed from a folder or a git tag, sandboxed on macOS.

**Architecture:** A new `AlloyRPC` target (moved out of `AlloyLSP`) carries the framing, `JSONRPCConnection` and `ServerProcess`. A new UI-free `AlloyPlugins` target holds the manifest, catalog, installer, the off-main `PluginHost` actor and the sandbox profile. In `AlloyKit`, one app-wide `@MainActor PluginCoordinator` (owned by `CommandCenter`) pumps an ordered stream to the host, applies contributions (themes, servers, registry commands, decorations, sidebar panels, MCP tools) and feeds the observable `PluginStatusModel` that only Settings › Plugins reads. Nothing plugin-related exists on the keystroke or idle-frame path.

**Tech Stack:** Swift 6 (strict concurrency), SwiftPM, MetalUI (read-only, `../MetalUI`), Swift Testing, `sandbox-exec` on macOS.

**Spec:** `docs/superpowers/specs/2026-11-16-plugins-design.md` (binding, with its "Approved decisions" and the "Updates (2026-11-23)" section Task 1 appends). Command seam: `docs/command-registry.md`.

## Global Constraints

- Branch `feat/plugins` in this worktree, tasks strictly in order. Never edit `../MetalUI`. A missing MetalUI API: stop and report it as a gap; never build a substitute.
- Tests run only as `lockf -k "$ALLOY_TEST_LOCK" swift test --no-parallel --filter <X>`. Builds: `swift build 2>&1 | grep -c "warning:"` prints `0`.
- Frame guards hold exactly; no task raises any guard constant: `ViewRerunTests.steadyFrameRequests` 46 (chat), `CodeModePerformanceTests.steadyCode1/2/3` 46/62/72, idle frames 0 element requests, `knownPopoverGap` 0, `steadyCompare` 77, `TerminalGuardTests` 0/0/55 (`knownVisibleTerminalGap`, `knownTerminalViewExcess`, `visiblePanelBaseline`). The spec's 88 and 91/107/117 are stale.
- Each task lands with its own tests and its own performance guard (named in the task).
- Theme roles only, no literal colours. Accessibility id on every interactive view. Zero warnings. Swift 6 strict concurrency.
- Alloy and plugins never write `~/.claude` or any project's `.claude/` (the theme-skill button is the only Alloy exception and is untouched).
- Secrets: Keychain only (service `dev.alloy.plugin-secret`, account `<plugin id>/<key>`); never in `settings.json`, a manifest, plugin state, logs or protocol messages. Alloy ships no keys.
- Linux and Windows: every file compiles there; platform calls sit behind `#if os(...)`. No sandbox backend is built for them, so no scripted plugin with `network` or `process.spawn` can be enabled there.
- Files a task writes (sources, tests, docs, the spec) hold no local absolute paths, usernames or session links. Commit only the task's files. Every commit message ends with the attribution trailers given in the task dispatch.
- Protocol details for plugin authors go into `docs/plugins.md` in the task that adds them (Task 2 creates it).
- No broad `pkill`; a test that spawns processes kills only its own PIDs (process groups included).

## Review Focus

- A `plugins` entry in `settings.json` whose folder is gone (deleted by hand, or a stale entry): Settings lists it as "folder missing" with Remove, nothing starts, no other plugin is affected. Pinned in Task 3 (`missingFolderIsListedAndInert`).
- Disabling or removing a plugin while one of its commands or requests is in flight: the request answers `-32800`, the command's task ends quietly, no toast and no crash. Pinned in Task 8 (`disableDuringCommandEndsQuietly`).
- Decoration items past the end of the document, inverted ranges or unknown roles: that item is dropped, the rest paint. Pinned in Task 9 (`outOfRangeItemsAreDroppedOthersPaint`).
- Quitting with plugins running: stdin closes, every group is gone within 2.5 s, `.running` is empty afterwards, quit is not held longer. Pinned in Task 7 (`quitStopsEveryGroupAndClearsRunningFile`).
- A plugin restarting while its panel tab is visible: the panel shows "Plugin stopped" until the next render, a focused TextField keeps its text. Pinned in Task 10 (`restartWhileVisibleKeepsFocusedText`).

## Rulings on spec conflicts (this plan's calls)

1. **`document/renamed` has no source.** Alloy has no file-tree rename and the watcher does not pair moves (a file moved outside becomes read-only "deleted outside"). v1 documents the message but never sends it; such a document gets `document/closed` when its tab closes.
2. **The "no backend" rule covers scripted processes.** Declarative `languageServers` and `taskCommands` still need the `process.spawn` grant, but they are Alloy's own server and terminal launches, never sandboxed on any platform; the enable prompt lists their exact commands. Scripted plugins with `network` or `process.spawn` need a sandbox backend (none until Task 17 on macOS, none on Linux/Windows).
3. **The sandbox never grants file-write into the project.** Writes go only through `project/write`, which keeps the `dirty`/`claudeEditing` refusals. `project/write` also refuses any path under `.git/` (`protectedPath`): writing git hooks would turn `project.write` into code execution.
4. **Hang and chatty restarts count as crashes** toward backoff and the 3-in-10-minutes auto-disable, so a stuck plugin cannot loop forever.
5. **Show log expands inline** under the plugin's row (a disclosure, like the plugin's settings), toggled by the Log button. No sheet or popover (orchestrator ruling: no workaround for MetalUI's missing `.sheet`).
6. **Plugin process environment is minimal:** `PATH` (login shell), `HOME`, `LANG`, `TMPDIR` (the plugin's scratch folder), `ALLOY_PLUGIN_ID`, plus the plugin's own secret variables. Working directory: the plugin folder.
7. **Plugin MCP tools are never pre-approved** (not in `--allowedTools`; ACP auto-allow skips `p_` tools). ACP sessions get Alloy's MCP server when sharing is on or a plugin tool scope applies, mirroring the Claude path.
8. **One `PluginCoordinator` per app**, owned by `CommandCenter`, bound to the current workspace by `CommandCenter.bind(_:)`.
9. **`window/showMessage` posts a workspace notice** (Alloy's existing notice strip), prefixed with the plugin name.
10. **Plugin settings changes are pushed** with a `settings/changed {values}` notification; grant and secret changes restart the process at its next activation instead.
11. **Sandbox read access is an allowlist, never a computed ancestor (M3 review, finding 1).** A scripted plugin reads its own folder, its scratch folder, the folder holding its main program (and its shebang interpreter) and the fixed read-only prefixes `/usr/lib`, `/usr/share`, `/System`, `/Library/Developer/CommandLineTools`, `/Applications/Xcode.app`, `/opt/homebrew`, `/usr/local`, `/bin`, `/usr/bin`, `/sbin`, `/usr/libexec` (plus `/dev/null`, `/dev/urandom`, `/dev/random`, the root directory entry itself, and the time zone files). The old "program's parent's parent" rule is gone: for `/bin/bash` it was `(subpath "/")`. A computed folder that is `/`, a top-level folder, the home folder or an ancestor of home is refused (`PluginSandboxError.grantTooBroad`; state `sandboxUnavailable`, log line says which folder); a folder already inside a fixed prefix needs no grant. Paths in the profile are canonical (`standardizedFileURL` folds `/private/var` back to `/var`, which the sandbox does not match).
12. **`#!` scripts start (finding 2).** `process-exec` allows the main file, its shebang interpreter, the `X` of `/usr/bin/env X` found on the plugin's PATH, and every file under the fixed read-only prefixes (children inherit the sandbox; the `xcrun` stubs behind `/usr/bin/python3` exec out of the Command Line Tools). Without `process.spawn` there is still no `process-fork`, so nothing can be forked, and nothing outside those prefixes can be exec'd: `spawnDeniedWithoutGrant` (fork of `/bin/sleep`) still means "fork is denied", and the new `execOfProgramOutsideTheSystemFoldersNeedsTheSpawnGrant` covers exec of a program outside them (with a control that runs with the grant). A bare `main.command` that is a file in the plugin folder now resolves to that file (it fell through to a PATH lookup before).
13. **No Mach service is reachable (finding 3).** The blanket `(allow mach-lookup)` is removed. The empirically required allowlist is empty: the Swift fake, `/bin/sh`, `/bin/bash`, Homebrew `python3`, the CLT `/usr/bin/python3` stub and a network-granted plugin (DNS) all run with no `mach-lookup` rule. With `process.spawn`, `/usr/bin/pbpaste` exits 1 with no output. With the `network` grant only, `com.apple.trustd.agent` and `com.apple.TrustEvaluationAgent` are added (found by bisecting all 2644 launchd service names): curl and URLSession then fetch HTTPS, and `pbpaste` still fails. Without the grant HTTPS fails.
14. **`network` is Internet, loopback and the resolver only (finding 4).** `(allow network-outbound (remote ip))`, `(allow network-inbound (local ip "localhost:*"))`, `(allow network-bind (local ip "localhost:*"))`, `(allow system-socket)`, read of `/private/etc/resolv.conf`, `/private/etc/hosts` and `/private/etc/ssl`, and `(allow network-outbound (literal "/private/var/run/mDNSResponder"))` for DNS. Unix-domain sockets (docker.sock) stay denied.
15. **Approved commands are hashed (finding 5).** `PluginSetting.approvedCommandsHash` is the SHA-256 of the language-server and task command lines the enable prompt showed (task lines are the POSIX-quoted lines with the manifest's own relative `cwd`). `enable` stores it; an update or reinstall keeps the old hash, so changed commands leave the plugin enabled-but-not-effective with the `needsPermissions` row state and a note. A manifest without such commands never needs approval. Settings saved before the hash existed: an enabled plugin whose manifest still has the version recorded in its entry is taken as unchanged and backfilled at the first scan; any other asks.
16. **Task fields never hold control characters, `cwd` is project-relative, Windows has no tasks yet (finding 6, Task 15 review).** The manifest loader refuses C0 control characters and DEL in a task's command, args, cwd and title, and refuses an absolute or `~` cwd. The enable prompt lists the exact quoted line that will be typed (for scripted plugins too). On Windows task commands are registered but disabled with the row note "Task commands aren't supported on Windows yet"; the Windows quoting branch is removed.
17. **Test sandbox overrides are injected, never global (finding 7).** `PluginHost` and `PluginCoordinator` take `sandbox: PluginSandboxOverride = .none`; `PassthroughSandbox.override` is passed explicitly by the rigs that want no profile, so suites cannot leak into each other or race in parallel runs.
18. **Git installer hardening (findings 8-10, 16).** `update(id:to:url:)` takes the URL recorded in settings and no longer reads `origin` from the plugin's own `.git/config`. Every git call starts with `-c protocol.ext.allow=never -c core.hooksPath=/dev/null -c submodule.recurse=false` and puts `--` before the URL and path; a URL or tag starting with `-` (or empty) is refused before anything is spawned; `GIT_LFS_SKIP_SMUDGE=1`; the size cap is checked once more after git exits. `PluginSemver` follows semver 2.0 precedence including pre-releases and ignores build metadata (`1.0.0-beta < 1.0.0`); a pre-release tag is offered only to a plugin that is on a pre-release.
19. **One update or git install at a time (findings 11-13).** `applyUpdate` and `install(gitURL:)` are no-ops while one runs for the same plugin (or at all, for the install); `availableUpdates[id]` is cleared before the first await; the row shows "Updating..." and its button is disabled, a moved tag can be checked again, and the git install button is disabled while it runs. `sandboxUnavailable` and `needsAPI` restore the previous version like `failedToStart`; stale `plugins/.<id>.previous` folders are deleted at launch.
20. **Plugin shortcuts need Command, Control or Option, or are F-keys (finding 15); shortcut notes are keyed by owner (finding 14).** Anything else is not bound and the row says why. `shortcutOwners` maps a command id to its plugin id, so changing `dev.a` no longer clears the notes of `dev.a.b`.

Contribution JSON shapes: `themes [{path}]`; `languageServers {<serverId>: <ServerConfigOverride>}` (server ids `^[a-z0-9-]{1,64}$`); `settings [{key, title, type: "bool"|"string"|"number"|"enum", options?: [String] (enum only, non-empty), default?}]`; `commands [{id, title, shortcut?, menu?: "plugins", when?}]`; `taskCommands [{id, title, command, args?, cwd?}]`; `panels [{id, title}]`; `mcpTools [{name, description, inputSchema}]`; `main {command, args?}`.

Validation (exact): file ≤ 256 KiB, a UTF-8 JSON object. Top-level keys only `id, name, version, apiVersion, description, main, permissions, activationEvents, contributes`; `contributes` keys only the seven above (anything else: `unknownKey("<path>")`). `id`: 1–100 chars of `[a-z0-9.-]`, at least one `.`, no leading/trailing `.`, no `..`, equal to the folder name. `name` 1–60 chars after trimming. `version` matches `^\d+\.\d+\.\d+(-[0-9A-Za-z.-]+)?$`. `apiVersion` an integer ≥ 1 (a value other than 1 is not a manifest error; the host reports it). `main.command`: a bare name (no `/`) found executable in `pathDirs`, or a relative path that resolves (symlinks followed) inside the folder, exists and is executable; absolute paths and paths escaping the folder are `mainOutsideFolder`.
