# Code intelligence core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Alloy hover, go to symbol, find references, format document/selection, format on save and a ⌘S Save command, all driven by a shared LSP request kernel.

**Architecture:** `LSPManager` gets capability parsing, a request kernel (`send`) that owns target lookup, capability check, barrier, version compare, position encoding, cancel and error mapping, and thin per-feature parsers; `definition` is refactored onto it. AlloyKit adds a main-actor wrapper per request on `LSPCoordinator`, a `PopoverSlotModel` for hover (slot B), a `ListPaletteModel` shown in Quick Open's field, and a `WorkspaceEditApplier` that all edit-producing features use. Format on save is an injected `Workspace.formatBeforeSave` hook.

**Tech Stack:** Swift 6.1, SwiftPM, MetalUI (read only), Swift Testing, the `AlloyFakeLSP` scripted server.

**Spec:** `docs/superpowers/specs/2026-11-16-code-intelligence-design.md` (read its "Approved decisions" section last; it is binding). This plan covers design tasks 1 to 5 only.

## Global Constraints

- Scope: capabilities and kernel (definition on it), raw diagnostic retention, `requestTargets`, fake server `replies`/`afterRequest`, hover, `ListPaletteModel`, go to symbol (⇧⌘O), references (⇧F12), `@` in ⌘P, `WorkspaceEditApplier`, format document/selection, formatter choice, ⌘S Save, format on save, settings. NOT in scope: rename, code actions/quick fixes, lightbulb, completion, signature help, snippets, the text context menu, `executeCommand`, answering `workspace/applyEdit` (wave 2; they need MetalUI gaps).
- Use ONE text-anchored presentation per `CodeView` (hover's `popover(item:attachmentAnchor:)`, slot B). MetalUI gap 4 is pending; never chain a second one.
- MetalUI is read only and never worked around. If an API is missing (or a hidden presentation raises a frame guard that cannot be avoided), STOP and report a MetalUI gap; build no substitute.
- Frame guards must not rise: `ViewRerunTests.steadyFrameRequests` 88 (Chat), `CodeModePerformanceTests.steadyCode1/2/3` 91/107/117. Idle frames cost 0 element requests and 0 body reruns. A hidden or closed feature costs nothing per frame. Never edit those constants upward.
- No cost per keystroke without a server: no timer, Task, observable write or request when `lspOpen` is false or the capability is missing.
- Theme values only; an accessibility id on every interactive view; zero warnings; never write `~/.claude` or a project's `.claude`.
- Decisions: 1(a) `Author.user` plus `public var group: UUID?` on `EditRecord` (optional, so synthesized Codable uses `decodeIfPresent`; add exactly that definition, search adds the same); 2(a) n/a here; 4(a) format on save only at deliberate saves (⌘S, focus leaving the editor, tab close); autosave never formats; 5(a) symbols in the palette only; 6(a) no Problems panel.
- Timeouts: hover 2 s; references, symbols 10 s; format document/selection 10 s (our call); format on save 750 ms. Caps: references 10,000 rows (palette shows 50, rest as a count line); decoded symbols 5,000.
- Menu items go in ONE new file, `Sources/AlloyKit/IntelCommands.swift`, hooked from `alloyCommands` by a single line. The registry branch lands first: on rebase the file's body becomes registrations in the shared `CommandRegistry`.
- Tests run only as: `lockf -k <the swift test lock> swift test --no-parallel [--filter X]` (called `TEST` below). `swift build` needs no lock. Known flaky if failing alone under load: `OverlapIndexTests.unsavedTypingCostIsBounded`, `ByteCopiesTests.readHoldsOneCopy`, `LSPManagerLinterTests.probeAnswersAreCachedUntilReload`.
- No subagents, no GUI launches, no broad pkill, no bare `git stash`, no Docker. Committed files contain no local paths or personal data (no home-directory paths, no usernames or emails, no sandbox temp paths, no session URLs, no bundle ids of the owner; the brief lists the exact leak-scan pattern). Every commit message ends with the two trailer lines from the task brief (Co-Authored-By Claude Opus 5.5, then Claude-Session).

## Review Focus

Failure modes the spec implies but a task's headline tests would not catch. Each has its test in the named task.

1. A server answers `null`, `[]` or an error for hover, references or symbols: no popover, "No references found", the inert "No symbols for this file" row, never a crash or a stuck palette. (Tasks 3, 4)
2. Format on save when the server is slow, crashes, errors, or the buffer moved while waiting: the file still saves (unformatted), no edit is lost or applied to the wrong text, one message per file per session. (Task 7)
3. Non-ASCII text (multi-byte, emoji surrogate pairs, CRLF) with UTF-16 and UTF-8 servers: hover ranges, symbol jumps and format edits land on the right bytes; an edit inside a surrogate pair or a UTF-8 sequence is rejected whole. (Tasks 2, 6, 7)
4. A references reply far over the cap (more than 10,000 hits, many files, files outside the root, binary or missing files): capped, responsive, outside-root hits counted not listed, no per-frame cost after. (Task 4)
5. Read-only document, old-text pane of side by side, document with no server, multiple carets (format selection), same file in two panes: items disabled instead of failing, no scheduler or popover state created, hover only where the pointer is. (Tasks 3, 7, 8)
6. The user types or switches tab while a request is in flight: the stale answer is dropped silently (no jump, no popover). (Tasks 3, 4)
