# Git v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everyday git inside Alloy's Code mode: gutter marks vs HEAD, file-tree status colours, a Git sidebar tab (stage, unstage, discard, commit), compare with HEAD/index with hunk actions, branch menu and picker, and on-demand blame.

**Architecture:** One hardened `GitProcess` runner (AlloyCore) runs the git CLI; pure parsers in `AlloyCore/Git/` turn porcelain output and `TextDiff` hunks into models. A `GitService` actor owns status, blob and blame caches and a 0.5 s coalescer; a `@MainActor GitCoordinator` (AlloyKit) wires it to the workspace hooks and publishes through three narrow surfaces (per-row tree cells, `GitPanelModel` for the Git tab, imperative gutter decorations under owner `git`). Nothing runs on idle frames or keystrokes.

**Tech Stack:** Swift, SwiftPM, MetalUI (read-only), Swift Testing, the git CLI (porcelain v2).

**Spec:** `docs/superpowers/specs/2026-11-16-git-design.md`, including its "Approved decisions" section. Scope here is spec tasks 1-10. Task 11 (MetalUI change lane, gutter hover, wider lane) is out of scope.

## Global Constraints

- Work only on branch `feat/git`. MetalUI is read-only; a missing MetalUI API is reported as a MetalUI gap, never worked around.
- Run tests only as: `lockf -k <the swift test lock> swift test --no-parallel [--filter X]` (use the lock path from the workflow brief, never write it into a file). `swift build` needs no lock. Known flaky under load, ignore if they fail alone: `OverlapIndexTests.unsavedTypingCostIsBounded`, `ByteCopiesTests.readHoldsOneCopy`, `LSPManagerLinterTests.probeAnswersAreCachedUntilReload`.
- Frame guards must not rise: `ViewRerunTests.steadyFrameRequests` 88; `CodeModePerformanceTests.steadyCode1/2/3` 91/107/117. Idle frames cost 0 element requests. A hidden or closed feature costs nothing per frame. No timer, poll or periodic `git status`; no git work on a keystroke.
- Every git run sets `GIT_TERMINAL_PROMPT=0` and `GIT_LITERAL_PATHSPECS=1`, and passes `--` before paths. Read runs also set `GIT_OPTIONAL_LOCKS=0`; write runs leave it unset. Alloy never runs `update-index --refresh`, `stash`, `reset`, `clean`, or a forced checkout, and never writes git config.
- Minimum git 2.23. Read timeout 10 s (SIGTERM at 10, SIGKILL at 12). Write runs: 120 s terminate, SIGKILL 5 s later. stderr capped at 64 KB.
- Marks: owner `CodeDecorationOwner("git", priority: -1)`; `.plain` presentation in Code mode only; diffs use `TextDiff.hunks(context: 0)`, run detached, skipped for buffers over 2 MiB. Compare uses context 3. Gutter marks recompute on save, outside change, HEAD change; `liveMarks` (750 ms typing idle on `autosaveClock`) is a setting, default off.
- Settings `AlloySettings.git`: `gutterMarks` on, `statusColours` on, `liveMarks` off, `gitPath` empty. `UIState` gains optional `codeSidebarTab: String?` ("files"/"git") and `gitCommitDraft: String?`, no `currentVersion` bump.
- Ledger edits made by revert hunk use `Author.user` plus the edit-group id. Revert over a pending Claude edit: confirm "This also reverts Claude's unreviewed change", then revert as an undoable buffer edit.
- Theme values only: new keys in `Theme.swift`, covered by `ThemeContrastTests`/`ContrastAuditTests`. Accessibility identifier on every interactive view. Zero warnings.
- Sidebar-tab plumbing stays minimal and isolated (the search branch adds `CodeLayout.sidebarTab`): all git tab state lives in `CodeSidebarModel`, and `CodeSidebarView.swift` changes only inside its tab row and content switch. Menu items are added in one small isolated function, `gitCommands(model:)`, called once from `alloyCommands`.
- No committed file may contain local paths or personal data (home-directory paths, the user's name or email, scratch directory names, session URLs, bundle ids); the brief gives the exact pattern, which is run as a sweep in Task 10. Commit messages end with the two trailer lines the brief gives (a Co-Authored-By line and a Claude-Session line), and nothing else after them.
- Never spawn subagents, launch GUI apps, use broad pkill/killall, bare `git stash`, or write to `~/.claude` or the project's `.claude`. Docker is not used.

## Review Focus

Failure modes the spec implies; each has a pinned test in the owning task.

1. A file name that starts with `-`, contains spaces, unicode, or looks like pathspec magic (`:(glob)x`) must stage, discard and show correctly. (Task 2 parser, Task 3 write commands.)
2. A CRLF buffer against an LF HEAD blob (`core.autocrlf`) must not mark every line modified, and a hunk patch must apply to the index's line endings. (Task 2.)
3. A file with no trailing newline, an empty file, and a hunk at the first or last line: marks, wedge row and `apply --cached` patches stay correct. (Task 2, Task 5.)
4. A project below the repo top, a linked worktree, and a renamed file (`R old -> new`) map to the right paths. (Task 2, Task 3.)
5. Hunk stage while the buffer is unsaved and the file partially staged; and a concurrent `index.lock`: error shows inline, no retry loop. (Task 3, Task 6, Task 7.)
