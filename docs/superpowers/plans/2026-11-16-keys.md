# Keyboard Settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Keyboard section in Settings that lists every registry command with its effective shortcut and lets the user record, clear, reset and reassign shortcuts, with clashes against built-in commands, MetalUI menu items, system keys and the code view's own keys shown.

**Architecture:** Overrides stay in `AlloySettings.keybindings` (already persisted, already drives `CommandRegistry.overrides` and `Keymap` through `Workspace.onKeybindingsChanged`). A pure AlloyCore editor (`KeybindingEditor`) turns "bind / clear / reset / reassign" into one new overrides dictionary, so a rebind plus its reassignment is one `Workspace.updateSettings` write. An AlloyKit classifier (`ShortcutClashes`) turns a candidate chord into hard conflicts (registry, own claims) and soft or informational ones (MetalUI standard menu, system, CodeView built-ins). `KeyboardSettingsSection` renders rows with MetalUI's `ShortcutRecorder`.

**Tech Stack:** Swift, SwiftPM, MetalUI (`ShortcutRecorder`, `KeyboardShortcut.conflicts(with:)`, `KeyboardShortcut.systemReserved(on:)`, `App.standardMenuShortcuts()`, `CodeView.builtInKeyBindings(platform:)`, `ClaimedShortcut`), Swift Testing.

**Spec:** `docs/superpowers/specs/2026-11-16-editor-essentials-design.md` (task 3; read "Approved decisions" at its end). Registry facts: `docs/command-registry.md`.

## Global Constraints

- Keymap is global (approved 3a); a conflict asks "Reassign from X?" (approved 2b); a rebind and its reassignment are one `AlloySettings` value written once, together or not at all.
- Only overrides are stored; Reset removes the key; `"none"` (`Keymap.unbound`) means explicitly unbound; unknown ids (newer Alloy) are kept on save and not shown; an unparseable chord is ignored.
- Rebind onto a MetalUI standard menu key, a system-reserved key or a hard CodeView built-in key is saved and flagged; the built-in still wins. CodeView entries with `isConditional` are soft: shown with their `condition`, never blocking.
- Theme values only (warning colour `.errorInk` or the theme's warning ink as other sections use). An accessibility id on every interactive view. Ids: `settings-keyboard`, `keyboard-filter`, `keyboard-reset-all`, `keyboard-row-<id>`, `keyboard-chord-<id>`, `keyboard-reset-<id>`, `keyboard-conflict-<id>`, `keyboard-builtin-<n>`, `keyboard-error`, plus `keyboard-reassign-confirm`, `keyboard-reassign-cancel`, `keyboard-clear-<id>`.
- Settings write failure: nothing applied, section shows "Could not save: …" in `keyboard-error`.
- Frame guards must not rise and no constant is raised: `ViewRerunTests.steadyFrameRequests`, `CodeModePerformanceTests.steadyCode1/2/3`, chat 46, code 46/62/72, knownPopoverGap 0, steadyCompare 77, terminal guards (knownVisibleTerminalGap 0), idle 0. Settings closed costs 0; the open section's idle costs 0; recorder idle (armed or not) costs 0.
- MetalUI is read-only. A missing API is a MetalUI gap: stop and report, no substitute.
- Zero warnings. Tests only through the swift test lock (`swift test --no-parallel`). No local paths or personal data in committed files. Commit messages end with the two trailer lines the project uses (Co-Authored-By and Claude-Session), as in the existing history.

## Review Focus

- Binding a chord to a command that already holds it, then Cancel on the prompt: nothing changes and nothing is saved (`KeyboardSettingsTests`, Task 5).
- Two clashes at once (another command AND a system key): the prompt names the command, the row also keeps the system flag (Task 4/5).
- Rebinding to the command's own default or its current chord: no prompt, override removed or unchanged (Task 2).
- Reset all with unknown-id and unparseable-value entries present: unknown ids survive, known ids are cleared (Task 2).
- Filtering to zero rows, then clearing the filter, and recording while a filter is set: rows return, edits target the right id (Task 4/5).
- `ctrl+x` vs `primary+x` clash off macOS only (Task 2, pure test with a platform flag).
- Settings window closed while recording or with the prompt open: no recording or stale prompt on reopen (Task 5).
