# CSV Table, Phase 2 remainder and Phase 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the CSV Table: row selection with Previous/Next change and reveal, row and cell Keep/Revert, cell mode with inline editing through one minimal `.programmatic` buffer transaction, whole-cell tints, and Table as the default for CSV and TSV in Code mode groups.

**Architecture:** AlloyCore keeps the logic UI-free: range-scoped keep on `FileLedger`/`EditHistory`, range keep and revert actions on `Workspace`, and a cell-edit pipeline (snapshot, map, refuse, encode, replace) on `CSVTableModel`. AlloyKit's `TablePanel` adopts MetalUI cell mode (`tableActiveCell`, `tableCellEditing`, `tableCellBackground`, `ScrollViewReader.scrollTo(TableCell)`), which landed in MetalUI master 44d3d68 (record 394). One byte-range primitive serves row, cell and deletion-marker Keep/Revert.

**Tech Stack:** Swift, SwiftPM, MetalUI `Table` cell mode (`TableCell<Int>{row, column}`; row id is the file ordinal, `CSVRowRef.id`), `MetalUICodeBuffer` (`CodeBuffer`, `buffer.map(_:from:bias:)`, `buffer.transaction`), `FileLedger`.

**Spec:** `docs/superpowers/specs/2026-11-20-csv-table-design.md` (binding; read "Approved decisions" at its end). Earlier plan: `docs/superpowers/plans/2026-11-16-csv.md` (its tasks 1-6 and the core of task 7, commit 7ecf588, are done; its tasks 7 UI and 8 are replaced by Tasks 1-3 here). Out of scope: column resize (PR D), cell accessibility (PR E), filtering, inserting or deleting rows or columns.

- Single-copy rule (`ByteCopiesTests`): no second copy of the file. Cell edits read one field from a snapshot range.
- Offsets are UTF-8 bytes. Cell edits, reverts and Keep go through `doc.buffer.transaction` with origin `.programmatic` (Keep changes the ledger only). The row terminator is never part of a cell. Quoting, spacing and line endings of untouched bytes stay byte-for-byte.
- Read-only documents (`doc.state != .editable`) and flagged rows never offer editing, Keep or Revert.
- A selectable row is a `.row` accessibility node with its cells (identifiers kept) as children; tests keep reading cells by identifier.

## Review Focus

Inputs the spec implies that no explicit test line covers; each is pinned in the task named.

1. Editing a cell, then an agent rewrites that file region before Return: the commit is refused with the notice and no bytes change; an agent edit elsewhere still commits at the mapped range (Task 5, Task 6).
2. A cell whose value contains the delimiter, quotes, a newline, or leading/trailing spaces, or an emptied value in a quoted field, round-trips and keeps untouched bytes (CRLF file, BOM file, last row without a newline) (Task 5).
3. Undo (cmd-Z) after a cell edit, and after a Keep, with the table on screen: bytes restored exactly, table updated from the change feed, no stale cell (Task 5, Task 6).
4. Keeping one cell of a multi-cell agent edit leaves the other cells tinted, and Revert of one cell on a sorted table acts on the file row, not the display position (Task 2, Task 3, Task 7).
5. A table in cell mode with 0 rows, a header-only file, or a ragged last row: arrow keys, Return and typing do nothing harmful and edit only an existing or missing-but-in-range cell (Task 4, Task 5).
