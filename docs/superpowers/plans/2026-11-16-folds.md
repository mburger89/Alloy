# Code folding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fold and unfold code in every Alloy code view: per-(pane, path) fold state, a fold-range coordinator (LSP over tree-sitter over indentation), gutter chevrons, four fold commands, and folds saved in `ui-state.json`.

**Architecture:** MetalUI owns the mechanics (`CodeFoldState`, `CodeView.foldState(_:)`, `foldGutter(showsOnHover:onToggle:)`, the `⋯` placeholder, caret eviction, edit tracking, `scrollRow(forLine:)`). Alloy adds (a) `Workspace+Folds` in AlloyCore, which keeps one `CodeFoldState` next to every `CodeSelectionState`, applies computed ranges and saved folds to them, and snapshots them for `UIState`; (b) `FoldCoordinator` in AlloyKit, which computes ranges off the main actor on the version settle and hands them to the workspace; (c) the view wiring, four registry commands, and a by-line scroll sync for side by side. No Alloy-drawn chevrons and no shadow line map.

**Tech Stack:** Swift, SwiftPM, Swift Testing, MetalUI (`MetalUICodeBuffer`, `MetalUITesting`).

**Spec:** `docs/superpowers/specs/2026-11-16-editor-essentials-design.md` (task 6 of its breakdown; read "Folding", "Persistence and settings", "Failure modes", "Performance plan", "Approved decisions" and "MetalUI design answers"). Registry contract: `docs/command-registry.md`. Fold sources (already merged, touched here only where a task says so): `IndentFolds`, `FoldMerge`, `HighlightEngine.foldRanges`, `LSPManager.foldingRanges`.

**Out of scope:** the fold sources themselves, keyboard settings (G7), fold-to-level commands, auto-fold on open, folding imports or comments as kinds, folds in chat transcript code blocks.

## Global Constraints

- Run tests only as: `lockf -k <the swift test lock> swift test --no-parallel [--filter X]` from the worktree root. Plain `swift build` needs no lock. Known flaky alone under load: `OverlapIndexTests.unsavedTypingCostIsBounded`, `ByteCopiesTests.readHoldsOneCopy`, `LSPManagerLinterTests.probeAnswersAreCachedUntilReload`.
- Frame guards hold exactly, and no constant is ever raised: chat `ViewRerunTests.steadyFrameRequests` 46; `CodeModePerformanceTests.steadyCode1/2/3` 46/62/72; `steadyCompare` 77; `knownPopoverGap` 0 in the Hover, Intel and Completion guards; idle frames cost 0 element requests. A hidden or closed feature costs nothing per frame.
- Use MetalUI master's G5/G6 as-is: `CodeFoldState` (`folded`, `foldableRanges`, `setFoldableRanges(_:asOf:)`, `fold`, `unfold`, `toggle`, `unfold(containing:)`, `unfoldAll`, `isHidden(line:)`), `CodeView.foldState(_:)`, `CodeView.foldGutter(showsOnHover:onToggle:)`, `CodeViewGeometry.scrollRow(forLine:)` / `line(forScrollRow:)`, `foldChevronRect(line:)`. If something is missing, stop and report a MetalUI gap; no workaround, no substitute.
- Line convention: `FoldRange` and `FoldLines` are 0-based inclusive `[start, end]`; MetalUI ranges are `start..<end + 1`. With a fold state attached, `CodeScrollPosition.row` counts shown rows.
- Fold source: one per document, never merged. LSP over tree-sitter over indentation; tree-sitter or indentation shows until LSP answers. An empty LSP answer counts as no answer. A windowed (large) document: LSP if it answers, else indentation, never tree-sitter. LSP times out after 1 s.
- Rebuilds run on the version settle, off the main actor, at most one in flight per document (a newer version cancels the older), and are applied only if the buffer version did not move. Never per keystroke.
- Persistence: `UIState.folds: [String: [String: [FoldLines]]]` keyed by pane (`"chat"` or the group UUID string) then project-relative path; `FoldLines` encodes as `[start, end]`; `UIState.version` stays 1; at most 2,000 folds per (pane, path), extras dropped from the end.
- Commands: Fold ⌥⌘←, Unfold ⌥⌘→, Fold All ⌥⇧⌘←, Unfold All ⌥⇧⌘→, in a Folding submenu of the View menu; menu ids `cmd-<id>`; disabled when no code view is focused; no registry rejections.
- Folds stay off the compare views (side by side and both git compares), which the spec does not mention; their scroll sync converts by line.
- Committed files contain no local paths or personal data (no home-directory paths, user names, scratch paths, session URLs, bundle prefixes or mail addresses). Commit messages end with exactly the two trailer lines the workflow supplies (Co-Authored-By and Claude-Session).

## Review Focus

Inputs the spec implies but its listed tests do not exercise; each is pinned by a test in the owning task.

1. A file with no foldable range, a one-line file and an empty file: no chevrons, all four commands are silent no-ops, no crash (Tasks 4, 5).
2. A tab or pane closed, or a document replaced (read-only becomes editable), while a build is in flight: nothing is applied to dead states, no state or pending fold leaks (Tasks 2, 3, 7).
3. Saved folds for a file that changed on disk and got shorter or lost the block: dropped quietly, never a crash, never a fold over the wrong lines (Task 2).
4. Fast typing: never two builds in flight for one document, a stale LSP answer is dropped, and an LSP that errors after having answered keeps its edit-tracked ranges instead of flipping to indentation and dropping folds (Task 3).
5. A large windowed document: indentation or LSP only, built off the main actor (Task 3). A document with 1,000 folds stays within the memory and persisted-size caps (Task 7).

## Notes for the executor
