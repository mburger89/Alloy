# Git Change Lane Adoption Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Git design task 11: move git's added/modified/deleted marks onto MetalUI's independent change lane, add gutter hover text for blame and change bars, and widen the file-blame marker lane to initials plus age, removing the interim author-bar-wins rule.

**Architecture:** `GitGutterMarks` (owner `git`, priority -1) emits `CodeLineDecoration(changeBar:)` instead of `gutterBar` and the wedge marker; `CodePanel.codeView(editable:)` reserves `changeLane(true)` while git marks can show for the document and installs one `gutterHelp` closure that computes text only when asked (MetalUI runs it in input on pointer moves, so steady frames cost nothing); file blame switches to `gutterMarkerLane(width:)` with "AL 3d" markers. Compare panes follow the same mark rule where MetalUI's lane applies.

**Tech Stack:** Swift, SwiftPM, MetalUI (read-only, at master f66a6913: #374 `CodeView.gutterHelp`, #375 `gutterMarkerLane(width:)`, #377 `CodeChangeBar`, `CodeLineDecoration.changeBar`, `CodeView.changeLane(_:)`, `CodeGutterHit.Source.changeBar`).

**Spec:** `docs/superpowers/specs/2026-11-16-git-design.md` (design task 11; "Two marks per row", "Editor gutter" sketch, "Gutter lane", "Known MetalUI gaps", Approved decisions 3(a) and 4(a)).

## Review Focus

- Git bar and author bar on the same row: both draw, neither hides the other (test in Task 2).
- File with git marks permitted but no hunks yet (tracked, clean): the lane is reserved from the first frame so the first hunk after a save does not shift text; an untracked file, a chat-mode file panel, inline and side-by-side presentations reserve no lane (Task 2).
- Deletion at first row, at last row and at end of file still anchors `deletedAbove` on a valid row (Task 1).
- Typing in a file with marks: no text shift, no extra frames, hover closure never runs (Tasks 2, 3).
- Hover over a blame marker on a row typed since the save, or over a stale tag after a recompute: returns nil or the nearest valid text, never crashes (Task 3).
- Blame marker for a very long author name or an age of years: marker text never exceeds the lane width (Task 4).
