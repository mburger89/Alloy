# Snippets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Accepting an LSP snippet completion starts a MetalUI snippet session (Tab and Shift-Tab step the placeholders, mirrors stay linked, Esc ends it) instead of inserting plain text.

**Architecture:** `CompletionApply.plan` learns to carry a parsed `CodeSnippet` next to the plain-text fallback. `IntelligenceScheduler.applyAccept` inserts it with `CodeSelectionState.insertSnippet(_:replacing:indentUnit:)`, then applies `additionalTextEdits`. MetalUI's `CodeView` already handles Tab, Shift-Tab and Esc through `CodeEditSession`, so Alloy writes no Tab stepping. The only key work is proving the completion popup (which sees keys first through `scheduler.handleKey`) and the session do not fight. Placeholders are tinted by a new theme token fed to `CodeTheme.snippetPlaceholder`.

**Tech Stack:** Swift, SwiftPM, MetalUI (`MetalUICodeBuffer.CodeSnippet`, `CodeSelectionState`, `CodeTheme`), Swift Testing, the `IntelRig` fake LSP server in `Tests/AlloyKitTests/IntelSupport.swift`.

**Spec:** `docs/superpowers/specs/2026-11-16-code-intelligence-design.md` (Goal 1 "Snippets"; Approved decisions 2(a), which this branch supersedes now that MetalUI gap 1 has shipped).

## Review Focus

- A snippet accepted while the buffer has several selections (a running session with mirrors, or multi-caret): primary caret only; the other selections must not be edited, and the outcome must not corrupt text.
- A snippet with `additionalTextEdits` before the insertion point (auto-import at the top of the file): the session's placeholder ranges must still point at the right text, and the import plus the snippet are one undo step.
- Typing a character inside a placeholder opens the completion popup; Tab then accepts the item (popup open) and the next Tab steps the session (popup closed).
- Esc with the popup open closes only the popup; the next Esc ends the session; the next collapses.
- A snippet item whose text is empty, only `$0`, or malformed (`${1:`): inserts as expected text, never traps, no session for `$0`-only.
- Read-only or non-editable buffer: nothing inserted, no stuck popup.
- Snippet insertion at a nested indent: later lines take the caret line's leading whitespace.
