How this is measured

  • The harness drives each app from outside, with synthetic input, and detects changes by comparing screen captures. It does not rely on anything the apps report about themselves.
  • Every metric is repeated and the page shows the median and the 95th percentile (p95) of the runs that survived. A run is dropped when its window never appeared, the screen changed before the window, or capture dropped frames; failures are listed in the run notes.
  • Startup and large-file open are strict: if any run is excluded the whole metric shows as not measured, never a median of survivors.
  • Pass bar: Alloy is at par with Zed when both its median and its p95 are within the larger of 5.0 % of Zed's value or an absolute floor (1.0 ms, 2.0 MiB, 0.1 %) of Zed's. It is ahead when both are lower than Zed's by more than that margin, and behind when either is higher by more than that margin. The headline counts at par and ahead.
  • A row is missing when Zed was measured but Alloy was not, and unjudged when Zed was not measured. Parity is judged against Zed only; Delta is shown for context.
  • Delta has no isolated profile option, so it runs against a normal Delta profile and state.
  • Scroll frame times cannot be lower than one display refresh period, so they floor at that value.
  • Results come from one machine and one run each time, so treat small differences with caution. Raw samples are in the JSON files linked below.
